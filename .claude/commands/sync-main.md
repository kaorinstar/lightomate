---
description: 最新の main をこのブランチにマージし、結果が壊れていないことを確認する
allowed-tools: Bash(git:*), Bash(sh:*), Read, Edit, Grep, Glob
---

このブランチを `main` の最新状態に合わせます。このリポジトリでは複数のセッションが同時に作業するため、
ブランチの作業中にも `main` が更新されます。最後にまとめて取り込むより、今マージするほうが負担が小さくなります。

次の順に作業し、失敗した手順で停止してください。

1. 現在の状態を報告します：`git status --short --branch`。コミットしていない変更がある場合は、
   先にコミットします。stash は使いません。stash は残したまま忘れやすいためです。
2. `git fetch origin main`
3. `git rev-list --count HEAD..FETCH_HEAD`。結果が `0` の場合はすでに最新です。その旨を報告して終了します。
4. マージする前に、取り込む内容を報告します：`git log --oneline HEAD..FETCH_HEAD` と
   `git diff --name-only $(git merge-base HEAD FETCH_HEAD) FETCH_HEAD`
5. `git merge --no-edit FETCH_HEAD`

   rebase は使わず、必ずマージします。rebase はほかのセッションやプルリクエストがすでに持っている
   コミットを書き換えます。このブランチは自分だけのものではありません。
6. 競合が起きた場合は、手作業で解決します。
   - 両方の変更の意図を残します。競合は 2 つのセッションが同じ行を変更したことを意味するため、
     片方を削除すると、すでに `main` にある作業を気付かないまま取り消すことになります。
   - `version.md` の `## Unreleased` の下での競合は、意見の相違ではなく追加どうしの競合です。
     両方の項目を残します。
   - 改行コードは LF です。ただし `.bat`、`.cmd`、`.ps1` は CRLF です。解決の過程で変えないでください。
   - その後 `git add <ファイル>` と `git commit --no-edit` を実行します。
   - どちらの動作が意図されたものか推測しなければ解決できない場合は、マージを途中のまま停止し、
     ユーザーに確認します。ビルドを通すために片方を選ぶことはしません。
7. マージ後の状態をビルドし、テストします。それぞれ正しい 2 つの変更が、組み合わせると誤りになる
   ことがあるためです。

   ビルドとテストの手順は、開発言語が決まった時点で `CLAUDE.md` に記載し、ここにも追記します。
   それまでは `sh .claude/hooks/check-main.test.sh` のみ実行します。
8. 次の順で報告します：取り込んだコミット数、競合したファイルとそれぞれの解決方法、ビルドとテストの
   結果。マージしたコミットが画面表示や操作の動作を変更している場合は、Windows 上で人が確認すべき
   項目も記載します。
