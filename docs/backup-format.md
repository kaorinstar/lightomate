# バックアップの形式

フローの管理画面の［設定］タブの「バックアップ」で書き出すファイルの形式です（#17）。
処理は `extension/shared/backup.js` にあります。このファイルと同時に変更します。

フローを 1 件ずつ、または選んで書き出すファイル（フロー 1 件のオブジェクトか、フローの配列）とは別の形式です。
フローのファイルは［保存したフロー］の［JSON から追加］で、バックアップは［設定］の［バックアップから復元］で
読み込みます。

## ファイル名

`lightomate-backup-<年月日>-<時分>.json`（例：`lightomate-backup-20260928-0930.json`）です。
Chrome のダウンロード先のフォルダーに保存します。

## 項目

| 項目 | 内容 |
|---|---|
| `kind` | `"lightomate-backup"` で固定です。フローのファイルと取り違えて読み込まないために使います。 |
| `version` | 形式の版です。現在は `1` です。Lightomate が扱える版より新しい場合は、復元しません。 |
| `exportedAt` | 書き出した日時（ISO 8601）です。復元では使いません。 |
| `flows` | `{ "id": "…", "flow": { … } }` の配列です。`flow` はフロー定義（`docs/flow-format.md`）です。`id` は、まとめフローから参照するために含めます。 |
| `batches` | まとめフローの配列です。各要素は `name`（名前）と `flowIds`（含めるフローの `id`、実行する順）です。 |
| `stopRules` | 必ず止まる場所です。オリジン（例：`https://www.example.com`）ごとに `selectors`（止める要素）と `paths`（止める画面）を持ちます。 |

```json
{
  "kind": "lightomate-backup",
  "version": 1,
  "exportedAt": "2026-09-28T00:30:00.000Z",
  "flows": [{ "id": "8d3c…", "flow": { "schemaVersion": 10, "name": "領収書", "origin": "https://www.example.com", "steps": [] } }],
  "batches": [{ "name": "月初の作業", "flowIds": ["8d3c…"] }],
  "stopRules": { "https://www.example.com": { "selectors": ["#placeOrder"], "paths": ["/checkout/*"] } }
}
```

ファイルには、実行時に入力する値の既定値も含まれます。値を記録していない入力欄（`secret`）の値は含まれません。

## 復元

復元は追加だけを行い、今あるデータを消しません。置き換えは既存のデータを失い、元に戻せないためです。

- 読み込む前に全件を検証します。1 件でも誤りがあれば、何も追加しません。
- **フロー**：保存済みのフローと内容が同じフローは追加しません（［JSON から追加］と同じ判定です）。
  同じサイトに同じ名前のフローがある場合は、名前に番号を付けます。追加したフローには新しい `id` を割り当てます。
- **まとめフロー**：`flowIds` を、追加したフロー（または同じ内容の保存済みのフロー）の `id` に付け替えます。
  ファイルに含まれないフローの `id` はそのまま残し、実行の前に誤りとして知らせます。同じ名前で同じフローを
  含むまとめフローがすでにある場合は、追加しません。
- **必ず止まる場所**：同じサイトの指定がすでにある場合は、保存済みの指定を残し、ファイルの内容は追加しません。
- 追加は 1 回の書き込みで行います。途中で失敗して、一部だけが復元された状態にはなりません。

同じファイルを 2 回復元しても、フロー、まとめフロー、必ず止まる場所は重複しません。
