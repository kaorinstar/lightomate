# 画面のデザインガイドライン

拡張機能の画面（サイドパネルと管理画面）の配置、見た目、知らせの出し方の規則です。画面を変更する
ときは、この文書に従います。規則を変える場合は、先にこの文書を変更します。

content script がページの中に出す表示（`extension/content/overlay.js`）は、ページの CSS の影響を
受けない Shadow DOM の中で描くため、この文書の対象外です。

## 1. 基本方針

- **Chrome の画面に溶け込む外観にします。** 部品は Tabler（https://tabler.io 、MIT ライセンス）の
  CSS を使い、独自の装飾を足しません。
- **サイドパネルは、表示中のサイトでフローを実行・記録する場所に絞ります。** JSON の編集、読み込み、
  サイトごとの設定は、管理画面に置きます。
- **誤りと確認は、押したボタンの直下に出します。** 画面の上部にまとめて出しません。成功の知らせだけは、
  画面の上部に固定した欄（トースト）に出し、5 秒後に消します（「5. 知らせと誤りの表示場所」）。

## 2. 画面の構成

### サイドパネル（1 列）

上から次の順に並べます。区画はそれぞれ Tabler の `card` です。進行中の作業はタブの上に置き、
タブを切り替えても見えるようにします（#7）。

1. **見出し**（常に表示）：アプリ名、表示中のサイト、「フローの管理」。
2. **進行中の作業**（該当する状態のときだけ表示）：上から、実行のカード、実行する値の入力、記録中、
   記録したフローの保存。実行のカードは、個別の実行とまとめフローの一括実行を区別せず、始めた日時の新しい順に
   上から並べます。新しく始めた実行は一番上に入ります。記録中と保存の区画では、手順の一覧の各行の右端に、その手順を削除する
   「×」を置きます。削除は 1 件ずつ即時に行い、確認を出しません。手順をすべて捨てる［破棄］は、確認してから行います。
   記録中の区画では、記録中のタブが記録を始めたサイト以外のページを表示しているとき、手順の一覧の上に
   「〜でも記録しています。」（許可があるサイト）か、「〜は許可していないため、記録していません。」と
   ［このサイトを許可して記録］（許可がないサイト）を表示します（#41）。
3. **タブ**（常に表示、#7）：［このサイトのフロー］［まとめフロー］。サイドパネルを開いたときは
   ［このサイトのフロー］を選びます。選んだタブは保存しません。Web ページ以外を表示しているときは、
   1 つ目のタブの名前を［すべてのフロー］にします。
4. **［このサイトのフロー］のタブ**：見出しの右に「記録開始」。各行はフロー名、手順数と更新日時、
   右端に「実行」と「…」。「…」を押すと、行の下に「名前の変更」「編集」「削除」が開きます。
   表示するのは、表示中のページのサイトが、フローの `origin`、`extraOrigins`、移動の手順の URL のサイトの
   いずれかと一致するフローです（#41）。
   Web ページ以外（新しいタブ、`chrome://` など）を表示しているときは、見出しを「すべてのフロー」にし、
   すべてのフローを管理画面と同じ検索欄とホスト名ごとの見出しで表示します。一致方法は検索欄の下に置きます。
   各行の「実行」の右に「開く」（最初のページを開く）を加えます（並びは「実行 → 開く → …」、#112）。
   区画の枠の外（直下）に、備考として「ほかのサイトのフローの確認、JSON の編集と読み込みは「フローの管理」で
   行います。」を置きます（#108）。「フローの管理」は、見出しの［フローの管理］と同じ画面を開くリンクです。
   すべてのフローを表示しているときは、「ほかのサイトのフローの確認、」を省きます。この画面で確認できるためです。

5. **［まとめフロー］のタブ**（#7）：各行はまとめフローの名前、フローの件数とサイト、右端に「実行」「すべて開く」。
   ［すべて開く］は、含めた各フローの最初のページを新しいタブで開き、手順は実行しません。URL が値を使う場合は、
   実行する値の入力と同じ区画で値を尋ねます。
   複数のサイトのフローを含むため、表示中のサイトにかかわらず同じ内容を表示します。まとめフローがない場合は、
   登録の方法を案内します。登録と削除は管理画面で行います。区画の枠の外（直下）に、［このサイトのフロー］のタブと同じ形の備考として、
   登録と削除の場所と実行のしかたを置きます（#108）。一覧の上に、フローの一覧と同じ検索欄と一致方法を置き、
   まとめフローの名前、含めたフローの名前、そのサイトのどれかで絞り込みます（#113）。候補には「まとめフロー」
   「フロー」「サイト」の種類を添えます。まとめフローがない場合は、検索欄を出しません。

記録中や、同じサイトのフローを実行中は、「実行」を押せない状態にし、理由を行の中に表示します。

実行のカードは、個別の実行とまとめフローで同じ形にします（#7）。情報を増やしすぎないよう、次のようにします。

- **1 行目**：名前、状態の印（「実行中」「一時停止中」「確定の手前で停止」「完了」など）、右端の操作。
  右端は、実行中は［実行停止］（まとめフローは［すべて中止］）、終わった後は［閉じる］です。
  まとめフローの印は全体の状態（「実行中」「操作待ち」「完了」「失敗あり」「終了」）です。
- **操作のボタン**：［一時停止］または［再開］、［タブを開く］、（失敗した場合）［フローを編集］。
  文より上に置き、文の長さが変わってもボタンの位置が動かないようにします（#98）。
- **進み具合の文**：フロー名を含めない短い文（「手順 2 / 5：クリック：注文履歴」など）を、小さい文字で出します。
  止まった場合は、その理由です。3 行までに省略し、マウスを重ねると全体を表示します。失敗は赤字にします。
  完了した場合は出しません。
- **まとめフロー**：2 行目に「まとめフロー・3 件中 1 件が終了」と進行のバー、その下にフローごとの行を並べます。
  各行の 1 行目も、フロー名、状態の印、右端の操作（まだ始めていないフローは［中止］の「×」）です。
  操作が必要な行（実行中・一時停止中・確定の手前・失敗）だけ、その下に［確認済み・次へ］［一時停止］または［再開］
  ［タブを開く］［中止］と、進み具合の文を出します。サイトと始めなかった理由は、フロー名にマウスを重ねると表示します。
  終わった後は、フローごとの行を［各フローの結果］（`details`）の中に畳みます。自動では消しません。
  失敗や未実行を見落とさないためです。
- **状態の印**は、役割の色を薄くした背景に、文字を 4.5:1 以上の濃さで書きます（`sidepanel.css` の `lm-status`）。
  色だけで伝えないよう、状態は文字で示します。

まとめフローに含まれる実行は、個別のカードには表示しません。［閉じる］では、含まれる実行の状態もあわせて消します。

### 管理画面（タブと list-detail）

1. **見出し**：「Lightomate」「フローの管理」。
2. **タブ**：［保存したフロー］［まとめフロー］［必ず止まる場所］［実行履歴］［設定］。5 つは対象も操作も別で、同時に見比べないためです。
   選んだタブは URL の `?tab=` に書き、再読み込みしても同じタブを開きます。
3. **［保存したフロー］のタブ**：左に一覧、右に選んだフローの詳細です。
   - 一覧：見出し「保存したフロー（件数）」と［JSON から追加］。その下に検索欄と一致方法（部分一致・前方一致・
     後方一致）。入力すると、欄の下に候補（`extension/shared/combobox.js`）を出し、一覧を即時に絞り込みます。
     その下に［すべて選択］のチェックボックス。1 件以上選ぶと、その下に「n 件を選択中」と［まとめフローとして保存］
     ［書き出し］［削除］の帯を出します。［まとめフローとして保存］を押すと、帯の下に名前の入力欄と、実行する順
     （選んだ順）の一覧、［保存］［キャンセル］を開きます（#7）。選択を外すときは［すべて選択］のチェックを外します。操作の対象は、一覧に表示中（検索で絞り込んだ結果）で選んでいるフローだけです。
     検索で表示から外れたフローの選択は外します。［削除］は帯の直下で確認し、実行中のフローは削除しません。
     一覧はホスト名ごとの折りたためる見出し（件数付き。選んでいる場合は「・n 件選択」も）の下に、左端の
     チェックボックスと、フロー名と「手順 n 件・更新 日時」の 2 行を並べます。チェックボックス以外の部分を
     押すと詳細を開きます。見出しはホスト名の順、見出しの中はフロー名の順です。
   - 詳細の見出し：フロー名（最も大きい文字）、サイト、手順数・実行時に入力する値の数・作成日時・更新日時。
     右に［実行］［最初のページを開く］［名前の変更］［ファイルに書き出し］［削除］。押せない場合は、理由を
     詳細の内容の先頭に案内（コールアウト）で表示します。値の入力が必要な場合は、同じ位置に枠で囲んだ入力フォームを出します。
   - 詳細の内容は、見出しと入力フォームの下のタブ（#132）に分けます。同時に見比べない内容を分け、下の区画を
     見るための長いスクロールをなくすためです。見出しの操作と入力フォームは、どのタブでも見えるようタブの上に置きます。
     - ［手順］（最初に選ぶタブ）：「実行時に入力する値」（ある場合だけ）と「手順」（番号、種類、説明。一時停止は
       黄色の帯で強調）。JSON を読まなくても、フローが何をするかがわかるようにするためです。
     - ［実行の速度］：手順の間隔の最短・最長の秒数と［速度を保存］。
     - ［定期実行］：状態、周期と時刻、［定期実行を保存］（#22）。
     - ［JSON］：「JSON を直接編集（上級者向け）」の編集欄と［JSON を保存］。
     - 別のフローを選んだときは、選んでいたタブのままにし、フローを見比べられるようにします。ただし［JSON］を
       選んでいた場合は［手順］に戻します。選んだタブは保存しません。タブを切り替えても、保存していない入力は
       消しません。
4. **［まとめフロー］のタブ**（#7）：説明文と、見出し「まとめフロー（件数）」の一覧。見出しの下に、
   サイドパネルと同じ検索欄と一致方法を置きます（#113）。各行は名前、実行する順の
   フロー（フロー名とサイト）、実行できない理由（削除されたフローを含む場合など、警告として表示）、［実行］［すべて開く］［削除］です。
   ［すべて開く］は、含めた各フローの最初のページを新しいタブで開き、手順は実行しません（詳細の［最初のページを開く］と同じ）。
   ［実行］［すべて開く］で値の入力が必要な場合は、行の中に枠で囲んだ入力フォームを開き、開いている間は［実行］［すべて開く］［削除］を隠します。
   実行の状態はサイドパネルに表示します。［削除］は行の中で確認します。登録は［保存したフロー］のタブで行います。
5. **［必ず止まる場所］のタブ**：説明文、左に指定したサイトの一覧と［新しいサイト］、右に入力欄。
6. **［実行履歴］のタブ**：説明文、見出し「実行履歴（件数）」と［CSV に書き出し］［すべて削除］、表（開始と終了、
   フローとサイト、結果、止まった手順と理由、保存したファイル、行の右端の［コピー］と「×」）。新しい順に並べます。
   結果は文字で示し、失敗と一時停止は色も付けます。［コピー］は成功以外の行にだけ置き、1 件の内容を貼り付けて
   報告できる形でコピーします（#93）。1 件ずつの削除は確認なしで行い、すべて削除は帯の直下で確認します。
7. **［設定］のタブ**：「サイトの許可」の区画に、「すべてのサイトを許可」のチェックボックスと説明文（#41）。
   チェックボックスは Chrome のサイトの許可そのものを表示し、切り替えます。許可が得られなかった場合は、
   チェックボックスの直下に知らせを出します。
   その下に「バックアップ」の区画（#17）。説明文と［すべて書き出し］［バックアップから復元］。復元は、ファイルを
   選んだ後、ボタンの直下で追加する件数とフローが操作するサイトを確認してから行います。誤りと、追加するものが
   ない場合の知らせは、確認と同じ位置に出します。
   その下に「免責事項」の区画（#109）。無保証、確定は人が行うこと、利用規約の確認は利用者が行うことの 3 点を
   箇条書きにし、`LICENSE` と `README.md` の「利用上の注意」の全文へのリンク（新しいタブで開く）を添えます。
   画面は要約とリンクに限り、詳しい内容は `README.md` を正とします。
8. **下部**：バージョン。

幅が 700px 以下の場合は、一覧と詳細を 1 列に並べます。

## 3. 部品の使い方

| 用途 | 使うもの |
|---|---|
| 区画 | `card`、`card-header`、`card-body` |
| 一覧 | `list-group`、`list-group-flush`、`list-group-item` |
| 主な操作（1 区画に 1 つ） | `btn btn-primary` |
| そのほかの操作 | `btn` |
| 元に戻せない操作（削除など） | 最初のボタンは `btn btn-ghost-danger`、確認の中の確定のボタンは `btn btn-danger` |
| 一覧の行の中の操作 | `btn-sm` を付ける |
| 入力欄 | `form-label`、`form-control`、`form-select` |
| 知らせ（誤り・警告） | `extension/shared/ui.js` の `showNotice`（`alert` を使います） |
| 成功の知らせ | `extension/shared/ui.js` の `showToast`。表示欄は `<div id="toast" class="lm-toast-region" role="status" aria-live="polite">` |
| 入力欄の誤り | `extension/shared/ui.js` の `showFieldError`（`is-invalid` と `invalid-feedback` を使います） |
| 確認 | `extension/shared/ui.js` の `confirmInline` |
| 備考（区画の外の補足、#108） | 枠と背景のない `lm-sub lm-aside`。先頭に `aria-hidden` の「ⓘ」を置きます。操作の結果ではなく常に表示する案内のため、「5. 知らせと誤りの表示場所」の知らせには含めません |
| 状態（実行の状態、実行履歴の結果、設定の状態） | 状態の印（`base.css` の `lm-status`）。設定の状態では、続けて内容を太字、補足を `lm-sub` で書きます（「要素ごとの見た目」） |
| 常に表示する案内（操作できない理由と対処など、#22） | `alert alert-info lm-guide`（`base.css`）。操作の結果ではないため、「5. 知らせと誤りの表示場所」の知らせには含めません（「要素ごとの見た目」） |

- 1 つの区画に `btn-primary` は 1 つだけ置きます。どれを押せばよいかを、色で示すためです。

### ボタンの並び（#112）

どの画面でも、次に押すボタンを同じ位置で見つけられるよう、並びをそろえます。

1. 並びは、左から「主な操作 → そのほかの操作（よく使う順）→ 元に戻せない操作 → キャンセル・閉じる」の順です。
2. 主な操作（`btn-primary`）は、1 つの並びに 1 つまでとし、並びの先頭に置きます。
3. 入力欄と確認のボタンは「確定（［保存］［削除する］［この値で〜］など）→［キャンセル］」の順です。
4. 一覧の行の右端の操作も、1 と同じ順です。「…」（その他の操作）は最後に置きます。
5. 元に戻せない操作は、最初に押すボタンを `btn-ghost-danger`、確認の中の確定を `btn-danger` とします。
   確認を出さずに即座に止める操作（［実行停止］［すべて中止］［記録停止］）は `btn-danger` とします。
6. 見出しの帯の操作と、カードの 1 行目の操作は右端に置きます。本文の中の並びは左に寄せます。

HTML に書いた並び（`lm-buttons`）は、`test/button-order.test.js` で 1〜3 を確かめます。画面の処理で作る並び
（一覧の行、実行のカード）は、この規則に沿って組み立て、Chrome 上で確かめます。
- Tabler の JavaScript は使いません。開閉は、状態を持つ画面側の処理か、`details` 要素で行います。
- 独自のクラスには `lm-` を付けます（例：`lm-notice`、`lm-sub`）。Tabler のクラスと区別するためです。
  両画面で使うものは `extension/shared/base.css`、片方だけのものは各画面の CSS に置きます。

### 要素ごとの見た目（#133）

公開されているデザインシステム（Carbon、Fluent 2、GOV.UK、Material Design 3）と NN/g の記事に基づく、
要素ごとの規則です。出典は「根拠とした一次情報」にあります。

- **状態の印**（`base.css` の `lm-status`）
  - 状態は、色だけでなく文字の名前でも示します。色は補助です。
  - 名前は 1〜2 語の状態を表す言葉（「実行中」「完了」「設定済み」）にし、「実行する」のような動詞にしません。
  - 押せる部品にしません。押せる見た目のボタンと区別するためです。
  - **同じ状態は、どの画面でも同じ名前と同じ色にします。** 実行の状態と実行履歴の結果は、
    `describe.js` の `runStatusLabel`・`runStatusTone` と `history.js` の `STATUS_LABELS`・`STATUS_TONES` を
    そろえます（`test/history.test.js` で確かめます）。
  - 色は次の 5 種類だけを使います。

    | 色 | 意味 | 例 |
    |---|---|---|
    | 緑（`success`） | 終わった、使える | 完了、設定済み |
    | 青（`primary`） | 進行中 | 実行中 |
    | 黄（`warning`） | 人の操作を待っている | 一時停止中、確定の手前で停止 |
    | 赤（`danger`） | 失敗した | 失敗 |
    | 灰（指定なし） | 止めた、まだない | 中止、未設定、待機中 |

- **常に表示する案内（コールアウト）**（`alert alert-info lm-guide`、注意は `alert-warning`）
  - 操作の結果ではなく、画面と一緒に表示する重要な案内に使います。例は、操作できない理由と、その対処です。
    操作の結果の知らせ（`showNotice`）とは使い分けます。
  - 先頭に「i」の印を付けた見出しを置きます。短い案内は見出しだけで構いません。長い案内は、見出しの下に
    本文と、「理由」「〜するには」などの小見出し付きの箇条書きを置きます。
  - 関係する区画・タブ・フォームの先頭に置き、1 つの区画に 1 つまでとします。閉じるボタンは付けません。
  - 情報（青）と注意（黄）だけに使います。誤り（赤）と成功（緑）は操作の結果のため、`showNotice` と `showToast` を使います。
  - 一覧の行の中の理由（サイドパネルの［実行］を押せない理由など）は、場所が狭いため、行の中の小さい文字（`lm-sub`）で示します。
- **備考（ⓘ、`lm-aside`）**：読まなくても操作に困らない補足だけに使います。必ず読んでほしい内容には、案内（コールアウト）を使います。枠と背景のない備考は、見落とされやすいためです。
- **空の状態**（`lm-empty`）
  - 一覧が空のときは、何もない枠を見せず、一覧の位置に文を置きます。
  - 文は「〜はまだありません。」に続けて、どうすれば作れるか（押すボタンの名前）を書きます。
  - 検索で該当しない場合は、「該当する〜はありません。」だけで構いません。利用者が自分の操作の結果だと分かるためです。
- **入力欄のまとまり**
  - 1 つの設定を作る入力欄の組（実行の速度の最短と最長、定期実行の周期と時刻など）は、見出しを持つ
    フォーム（`aria-labelledby` で見出しを指す `form`）か、`fieldset` と `legend` でまとめます。
  - 読み上げで、どの設定の欄かが分かるようにするためです。
- **強調**
  - 強調（色、太さ、囲み）は、1 つの区画で最も重要な 1 つの操作か情報だけに使います。主な操作は `btn-primary`、
    重要な案内はコールアウトです。
  - M3 Expressive のうち、形の変化や動きによる強調は採り入れません。業務の道具として、落ち着いた見た目を保つためです。

## 4. 色・余白・文字

- **色**：Tabler の CSS 変数（`--tblr-primary`、`--tblr-danger`、`--tblr-secondary` など）だけを使い、
  色コードを直書きしません。明るい表示と暗い表示で、同じ指定のまま色が切り替わるようにするためです。
- **コントラスト**：文字と背景のコントラスト比を 4.5:1 以上にします。Tabler の標準の知らせの色は、
  明るい表示で基準に届かないもの（黄色で約 2:1）があるため、`base.css` で文字色を調整しています。
  色を変えたときは、作業環境の Chromium で両方の表示の文字色と背景色を取得し、比を計算して確認します。
- **余白**：4px の倍数（4、8、12、16、24px。rem では 0.25、0.5、0.75、1、1.5）だけを使います。
  区画どうしの間は、サイドパネルで 12px、管理画面で 16px です。
  カードの本文と一覧の 1 行の上下の余白は、両画面で 12px です（Tabler の標準の 20px を `base.css` で上書き）。
- **文字**：次の段階だけを使います。見出しと本文の差は、大きさと太さの両方で付けます。

  | 段階 | 用途 | 管理画面 | サイドパネル | 太さ | クラス |
  |---|---|---|---|---|---|
  | 画面見出し | 「フローの管理」、サイドパネルの「Lightomate」 | 24px | 16px | 700 | `lm-screen-title`、`lm-title` |
  | 詳細の見出し | 管理画面の詳細のフロー名 | 20px | （なし） | 700 | `lm-detail-name` |
  | 区画見出し | カードの見出し、タブ、詳細の中の節（「手順」など） | 16px（タブは 15px） | 14px | 700（タブは 600） | `card-title`、`lm-tabs`、`lm-block-title` |
  | 項目名 | 一覧のフロー名、入力欄の項目名 | 15px（項目名は 14px） | 14px | 600 | `lm-item-name`、`lm-flow-name`、`form-label` |
  | 本文 | 説明、手順の説明、ボタン、入力欄 | 14px | 13px | 400 | （指定なし） |
  | 補足 | 日時、件数、サイト、注記、小さいボタン | 12px | 12px | 400 | `lm-sub`、`btn-sm` |

  サイドパネルは幅が狭く、大きい文字では 1 行に入る文字数が減り、フロー名の折り返しが増えるため、
  管理画面より 1 段ずつ小さくします（#115）。サイドパネルの指定は `sidepanel.css` の先頭にまとめています。
  12px より小さい文字は使いません。Windows の日本語フォントでは、画数の多い漢字がつぶれやすいためです。

  **太さは 400・600・700 だけを使い、500 は使いません。** 日本語のフォント（Windows の Meiryo など）は
  太さ 500 を持たないことが多く、通常の太さで表示されるためです。Tabler の見出しは 500 のため、
  `base.css` で 700 に上書きしています。区画見出しの帯（`card-header`）は、内容より一段濃い背景にします。
  画面を変えたときは、撮影した画像をぼかして見ても、見出しが先に目に入るかを確かめます。
- **暗い表示**：OS の設定に従います（`extension/shared/ui.js` の `followColorScheme`）。

## 5. 知らせと誤りの表示場所

### 見た目の使い分け

知らせの見た目は次の 4 種類だけを使います。見た目で、何についての知らせかを区別できるようにするためです。

| 見た目 | 部品 | 使う場面 |
|---|---|---|
| 赤字だけ（入力欄に赤枠） | `showFieldError`（`invalid-feedback`） | 特定の入力欄・選択欄に対する誤り。その欄の直下に出す |
| 枠で囲んだ知らせ | `showNotice`（`alert`） | どの入力欄の誤りか特定できない失敗と、警告。押したボタンの直下に出す |
| ボタンを含む枠 | `confirmInline` | 元に戻せない操作の確認。押したボタンの直下に出す |
| 上部のトースト | `showToast` | 成功の知らせだけ |

- **入力欄に対する誤りを、枠で出しません。** 複数の欄の誤りでも、それぞれの欄の直下に分けて出します。
  JSON の編集欄のように、欄の中の位置を指せない誤りも、編集欄の直下に出します。
- **Chrome 標準の吹き出し（`required` などによる検証）は使いません。** 見た目と位置が、ほかの誤りと
  異なるためです。フォームには `novalidate` を付け、画面の処理で検証します。
- 検証は、ボタンを押したときに行います。誤りのある最初の欄にフォーカスを移し、欄を直し始めたら、その欄の
  誤りを消します。

### 表示場所

成功の知らせは、画面の上部に固定した欄（トースト）に出します。スクロールした位置にかかわらず見えるためです。
誤り・警告・確認は、押したボタンの直下に出します。自動で消える表示は見落とされ、画面の上部に出す表示は、
どの操作についての知らせかが位置から読み取れないためです。

| 種類 | 表示場所 | 消え方 | 例 |
|---|---|---|---|
| 操作の成功 | 画面の上部のトースト（`showToast`） | 5 秒後、または［✕］で消える。マウスを重ねている間とフォーカスがある間は消さない | 保存しました、コピーしました、削除しました |
| 見落とすと困る成功 | 押したボタンの直下に、警告として出す | 次の操作を始めるまで消さない | 同じ名前があるため、番号を付けて保存した |
| 操作の失敗・警告 | 押したボタンの行の直下 | 次の操作を始めるまで消さない | 保存の失敗、許可が得られない、実行を開始できない |
| 入力の誤り | その入力欄の直下（赤枠と文言） | 入力を直すと消える | フロー名が空、実行する値の形式、止める画面が / で始まらない |
| JSON の形式の誤り | 編集欄の直下（編集欄とボタンの間）に誤りの一覧。編集欄に赤枠 | 入力を直すと消える | 管理画面の保存と追加 |
| 元に戻せない操作の確認 | 押したボタンの行の直下（`confirmInline`） | 選択するまで消さない | 削除の確認、破棄の確認 |
| 実行の状態 | その実行の区画の中 | 実行の区画が閉じるまで残る | 手順が見つからない、確定ボタンの手前で止まった |
| 画面全体の状態 | 一覧の区画の中の空表示 | 状態が変わるまで残る | 該当するフローはありません |

- **入力欄や確認を開いている間は、開くために押したボタンの並び（同じ行・同じ帯のボタン）を隠します**（#112）。
  ［キャンセル］、［保存］、確定のいずれかで閉じたときに表示し直します。元のボタンが残ると、目が上のボタンに
  向き、入力欄や確認の中のボタンを見落とすためです。確認は `confirmInline` の `hide` に隠す要素を渡します。
  サイドパネルの値の入力フォームを開いている間は、一覧の行の操作と［記録開始］を隠します。
- **トーストには、結果が画面のほかの場所にも残る知らせだけを出します。** 保存したフローは一覧に増え、
  削除したフローは一覧から消えるため、トーストを見落としても結果を確認できます。
- **見出しの帯にあるボタン**（サイドパネルの［記録開始］［記録停止］、管理画面の［名前の変更］［削除］）の
  誤りと確認は、帯の直下（本文の先頭）に出します。帯の中には置きません。
- **区画が閉じる操作**で名前に番号を付けた場合は、そのフローが表示される行または区画に警告を出します。
  例：記録したフローの保存（一覧の行）、JSON からの追加（詳細の区画）。
- 表示欄が画面の外にある場合は、見える位置まで移動します（`showNotice` が行います）。
- トーストは 1 つだけ表示し、新しいトーストは前のトーストと置き換えます。フォーカスは移しません。
- 誤りと警告は、次の操作を始めたときに消します。
- 誤りは文字と記号で示し、色だけで伝えません。
- 読み上げのため、誤りは `role="alert"`、それ以外は `role="status"` にします（`showNotice` が設定します）。
  トーストの表示欄は `role="status"` とし、読み上げの対象から外れないよう、空のまま常に置いておきます。
- ブラウザ標準の `confirm()` と `alert()` は使いません。画面の中央に出るため、どの操作の確認かが
  位置から読み取れないためです。
- 表示欄と対象のボタン、入力欄と誤りの表示欄の組み合わせは、`test/notice-placement.test.js` で確かめます。
  表示欄や入力欄を追加したときは、このテストの一覧にも追加します。

## 6. 文の書き方

- 誤りの文は「何が起きたか」と「どうすれば直るか」を書きます。
  例：「https://example.com を操作する許可が得られなかったため、続けられません。もう一度押し、表示される
  画面で「許可」を選んでください。」
- 入力欄の誤りは、指示の形で書きます。例：「フロー名を入力してください。」
- 「エラーが発生しました」のような、原因を示さない文は使いません。
- 確認の文は、何が起きるかと、元に戻せるかを書きます。例：「「月次の領収書を保存」を削除します。
  元に戻せません。」確定のボタンには、動作の名前（「削除する」）を付けます。「OK」は使いません。

## 7. Tabler の同梱

- 拡張機能の CSP は外部からの読み込みを禁止しているため、Tabler の CSS は `extension/vendor/tabler/` に
  同梱します。版は `package.json` の `@tabler/core` で管理し、`npm run vendor` で複写します。
  `test/vendor.test.js` が、同梱したファイルと `node_modules` の同じ版のファイルが一致するかを確認します。
- Tabler は、入力欄の誤りの印とセレクトボックスの矢印を `data:` の画像で描きます。拡張機能の CSP は
  `data:` の画像を許可していないため、`base.css` でこれらを使わない指定に置き換えています。
  Tabler の部品を新しく使うときは、`data:` の画像を使っていないかを確認します。
- Tailwind CSS は使いません。使うクラスを走査して CSS を生成する工程が必要で、このリポジトリの
  「ビルド工程なし」の方針に合わないためです。
