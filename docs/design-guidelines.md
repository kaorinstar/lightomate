# 画面のデザインガイドライン

拡張機能の画面（サイドパネルと管理画面）の配置、見た目、知らせの出し方の規則です。画面を変更する
ときは、この文書に従います。規則を変える場合は、先にこの文書を変更します。

content script がページの中に出す表示（`extension/content/overlay.js`）は、ページの CSS の影響を
受けない Shadow DOM の中で描くため、この文書の対象外です。

## 1. 基本方針

- **Chrome の画面に溶け込む外観にします。** 部品は Tabler（https://tabler.io 、MIT ライセンス）の
  CSS を使い、独自の装飾を足しません。
- **サイドパネルは、表示中のサイトでフローを実行・記録する場所に絞ります。** JSON の編集、読み込み、
  サイトごとの設定は、管理画面に置きます。
- **知らせは、操作した場所に出します。** 画面の上部にまとめて出しません（「5. 知らせと誤りの表示場所」）。

## 2. 画面の構成

### サイドパネル（1 列）

上から次の順に並べます。区画はそれぞれ Tabler の `card` です。

1. **見出し**（常に表示）：アプリ名、表示中のサイト、「フローの管理」。
2. **進行中の作業**（該当する状態のときだけ表示）：実行の状態（実行ごとに 1 枚）、実行する値の入力、
   記録中、記録したフローの保存。記録中と保存の区画では、手順の一覧の各行の右端に、その手順を削除する
   「×」を置きます。削除は 1 件ずつ即時に行い、確認を出しません。手順をすべて捨てる［破棄］は、確認してから行います。
3. **このサイトのフロー**（常に表示）：見出しの右に「記録開始」。各行はフロー名、手順数と更新日時、
   右端に「実行」と「…」。「…」を押すと、行の下に「名前の変更」「編集」「削除」が開きます。

記録中や、同じサイトのフローを実行中は、「実行」を押せない状態にし、理由を行の中に表示します。

### 管理画面（タブと list-detail）

1. **見出し**：「Lightomate」「フローの管理」。
2. **タブ**：［保存したフロー］［必ず止まる場所］。2 つは対象も操作も別で、同時に見比べないためです。
   選んだタブは URL の `?tab=` に書き、再読み込みしても同じタブを開きます。
3. **［保存したフロー］のタブ**：左に一覧、右に選んだフローの詳細です。
   - 一覧：見出し「保存したフロー（件数）」と［JSON から追加］。サイトごとの見出し（件数付き）の下に、
     フロー名と「手順 n 件・更新 日時」を 2 行で並べます。
   - 詳細の見出し：フロー名（最も大きい文字）、サイト、手順数・実行時に入力する値の数・作成日時・更新日時。
     右に［名前の変更］［ファイルに書き出し］［削除］。
   - 詳細の内容：「実行時に入力する値」（ある場合だけ）、「手順」（番号、種類、説明。一時停止は黄色の帯で
     強調）、「JSON を直接編集（上級者向け）」（折りたたみ。開くと編集欄と［JSON を保存］）。
     JSON を読まなくても、フローが何をするかがわかるようにするためです。
4. **［必ず止まる場所］のタブ**：説明文、左に指定したサイトの一覧と［新しいサイト］、右に入力欄。
5. **下部**：バージョン。

幅が 700px 以下の場合は、一覧と詳細を 1 列に並べます。

## 3. 部品の使い方

| 用途 | 使うもの |
|---|---|
| 区画 | `card`、`card-header`、`card-body` |
| 一覧 | `list-group`、`list-group-flush`、`list-group-item` |
| 主な操作（1 区画に 1 つ） | `btn btn-primary` |
| そのほかの操作 | `btn` |
| 元に戻せない操作（削除など） | 最初のボタンは `btn btn-ghost-danger`、確認の中の確定のボタンは `btn btn-danger` |
| 一覧の行の中の操作 | `btn-sm` を付ける |
| 入力欄 | `form-label`、`form-control`、`form-select` |
| 知らせ | `extension/shared/ui.js` の `showNotice`（`alert` を使います） |
| 入力欄の誤り | `extension/shared/ui.js` の `showFieldError`（`is-invalid` と `invalid-feedback` を使います） |
| 確認 | `extension/shared/ui.js` の `confirmInline` |

- 1 つの区画に `btn-primary` は 1 つだけ置きます。どれを押せばよいかを、色で示すためです。
- Tabler の JavaScript は使いません。開閉は、状態を持つ画面側の処理か、`details` 要素で行います。
- 独自のクラスには `lm-` を付けます（例：`lm-notice`、`lm-sub`）。Tabler のクラスと区別するためです。
  両画面で使うものは `extension/shared/base.css`、片方だけのものは各画面の CSS に置きます。

## 4. 色・余白・文字

- **色**：Tabler の CSS 変数（`--tblr-primary`、`--tblr-danger`、`--tblr-secondary` など）だけを使い、
  色コードを直書きしません。明るい表示と暗い表示で、同じ指定のまま色が切り替わるようにするためです。
- **コントラスト**：文字と背景のコントラスト比を 4.5:1 以上にします。Tabler の標準の知らせの色は、
  明るい表示で基準に届かないもの（黄色で約 2:1）があるため、`base.css` で文字色を調整しています。
  色を変えたときは、作業環境の Chromium で両方の表示の文字色と背景色を取得し、比を計算して確認します。
- **余白**：4px の倍数（4、8、12、16、24px。rem では 0.25、0.5、0.75、1、1.5）だけを使います。
  区画どうしの間は、サイドパネルで 12px、管理画面で 16px です。
- **文字**：次の段階だけを使います。見出しと本文の差は、大きさと太さの両方で付けます。

  | 段階 | 用途 | 大きさ | 太さ | クラス |
  |---|---|---|---|---|
  | 画面見出し | 「フローの管理」、サイドパネルの「Lightomate」 | 24px（サイドパネルは 20px） | 700 | `lm-screen-title`、`lm-title` |
  | 詳細の見出し | 管理画面の詳細のフロー名 | 20px | 700 | `lm-detail-name` |
  | 区画見出し | カードの見出し、詳細の中の節（「手順」など） | 16px | 700 | `card-title`、`lm-block-title` |
  | 項目名 | 一覧のフロー名、入力欄の項目名 | 15px（項目名は 14px） | 600 | `lm-item-name`、`lm-flow-name`、`form-label` |
  | 本文 | 説明、手順の説明 | 14px | 400 | （指定なし） |
  | 補足 | 日時、件数、サイト、注記 | 12px | 400 | `lm-sub` |

  **太さは 400・600・700 だけを使い、500 は使いません。** 日本語のフォント（Windows の Meiryo など）は
  太さ 500 を持たないことが多く、通常の太さで表示されるためです。Tabler の見出しは 500 のため、
  `base.css` で 700 に上書きしています。区画見出しの帯（`card-header`）は、内容より一段濃い背景にします。
  画面を変えたときは、撮影した画像をぼかして見ても、見出しが先に目に入るかを確かめます。
- **暗い表示**：OS の設定に従います（`extension/shared/ui.js` の `followColorScheme`）。

## 5. 知らせと誤りの表示場所

知らせは、利用者が操作した場所に出します。画面の上部の 1 か所にまとめると、画面の下部で操作した
ときに、知らせが見えない位置に出るためです。

| 種類 | 表示場所 | 例 |
|---|---|---|
| 入力の誤り | その入力欄の直下（赤枠と文言） | フロー名が空、サイトの形式の誤り |
| 操作の失敗 | その操作をした区画・行の中 | 保存の失敗、許可が得られない、実行を開始できない |
| JSON の形式の誤り | 編集欄の上に誤りの一覧。編集欄に赤枠 | 管理画面の保存と追加 |
| 実行の失敗・停止 | その実行の区画の中 | 手順が見つからない、確定ボタンの手前で止まった |
| 操作の成功 | その操作をした区画の中 | 保存しました、コピーしました |
| 区画や行が消える操作の結果 | 一覧の区画の先頭 | 削除しました、保存して記録の区画が閉じた |
| 画面全体の状態 | 一覧の区画の中の空表示 | このページでは使えません |
| 元に戻せない操作の確認 | 操作した行・区画の中 | 削除の確認 |

- 知らせは、次の操作を始めたときに消します。
- 誤りは文字と記号で示し、色だけで伝えません。
- 読み上げのため、誤りは `role="alert"`、それ以外は `role="status"` にします（`showNotice` が設定します）。
- ブラウザ標準の `confirm()` と `alert()` は使いません。画面の中央に出るため、どの操作の確認かが
  位置から読み取れないためです。

## 6. 文の書き方

- 誤りの文は「何が起きたか」と「どうすれば直るか」を書きます。
  例：「https://example.com を操作する許可が得られなかったため、続けられません。もう一度押し、表示される
  画面で「許可」を選んでください。」
- 入力欄の誤りは、指示の形で書きます。例：「フロー名を入力してください。」
- 「エラーが発生しました」のような、原因を示さない文は使いません。
- 確認の文は、何が起きるかと、元に戻せるかを書きます。例：「「月次の領収書を保存」を削除します。
  元に戻せません。」確定のボタンには、動作の名前（「削除する」）を付けます。「OK」は使いません。

## 7. Tabler の同梱

- 拡張機能の CSP は外部からの読み込みを禁止しているため、Tabler の CSS は `extension/vendor/tabler/` に
  同梱します。版は `package.json` の `@tabler/core` で管理し、`npm run vendor` で複写します。
  `test/vendor.test.js` が、同梱したファイルと `node_modules` の同じ版のファイルが一致するかを確認します。
- Tabler は、入力欄の誤りの印とセレクトボックスの矢印を `data:` の画像で描きます。拡張機能の CSP は
  `data:` の画像を許可していないため、`base.css` でこれらを使わない指定に置き換えています。
  Tabler の部品を新しく使うときは、`data:` の画像を使っていないかを確認します。
- Tailwind CSS は使いません。使うクラスを走査して CSS を生成する工程が必要で、このリポジトリの
  「ビルド工程なし」の方針に合わないためです。
