# フロー定義の形式（版 19）

Lightomate が記録した操作は、この形式の JSON になります。検証の処理は
`extension/shared/flow.js` にあり、この文書と処理の内容が一致している必要があります。形式を変える場合は、
両方を同時に変更し、`schemaVersion` を 1 増やします。

記録できる操作は、ページの移動、クリック、文字の入力、選択肢の選択の 4 種類です。パラメータ（実行の
たびに変わる値）を定義できます。条件分岐（`if`）と繰り返し（`forEach`、`while`）は、管理画面の［手順］タブのブロックで
加え、対象の要素はページの上で選びます（#139）。JSON を直接編集して加えることもできます。

## 全体

```json
{
  "schemaVersion": 4,
  "name": "記録 2026/9/24 14:04:24",
  "origin": "https://www.example.com",
  "steps": [
    { "type": "navigate", "cause": "user", "url": "https://www.example.com/login" },
    { "type": "input", "target": { "...": "..." }, "value": "taro@example.com" },
    { "type": "input", "target": { "...": "..." }, "secret": true },
    { "type": "click", "target": { "...": "..." } },
    { "type": "navigate", "cause": "page", "url": "https://www.example.com/orders" }
  ]
}
```

| 項目 | 内容 |
|---|---|
| `schemaVersion` | 形式の版番号。現在は `19` です。`1`〜`18` のフローも読み込めます。 |
| `name` | フロー名。記録した日時が初期値です。同じ `origin` に同じ名前のフローがある状態で保存すると、既存のフローを上書きせず、名前に番号を付けて保存します（例：`領収書 (2)`）。 |
| `origin` | 記録を始めたページのオリジン（`https://` または `http://` と、ホスト名とポート番号）。 |
| `extraOrigins` | 記録を始めたサイトのほかに、手順を記録したサイトのオリジンの一覧（下記の「複数のサイトを操作するフロー」）。省略できます。10 件までで、`origin` と同じ値や重複は書けません。版 5 で加えました。 |
| `params` | パラメータの定義（下記の「パラメータ」）。省略できます。 |
| `interval` | 手順と手順の間に待つ時間（下記の「手順の間隔」）。省略できます。 |
| `steps` | 手順の一覧。記録した順に並びます。上限は、`if` と `forEach` の内側の手順を含めて 1,000 件です。 |

## 複数のサイトを操作するフロー

ログイン画面や買い物かごが、別のサブドメインや別のサイトにあるサイトがあります（例：楽天市場は、商品
ページが `item.rakuten.co.jp`、買い物かごが `cart.step.rakuten.co.jp`、ログイン画面が
`login.account.rakuten.com`）。このようなサイトのため、フローは複数のサイトを操作できます（#41）。

- 記録中に別のサイトへ移動した場合、そのサイトを操作する許可があれば、確認を出さずに記録を続けます。
  許可がなければ、サイドパネルの最上部の知らせの［このサイトを許可して記録を続ける］で許可すると記録を続けます（#209）。
  すべてのサイトの許可（#232）を持っている間は、常に許可があります。
- 記録を始めたサイト以外で記録したクリック・入力・選択・読み取りの手順には、そのサイトを `origin` として
  書き、そのサイトを `extraOrigins` に加えます。転送で通過しただけのサイトは加えません。
- 実行時、クリック・入力・選択・読み取りは、その手順の `origin`（ない場合はフローの `origin`）と同じサイトの
  ページでだけ行います。別のサイトのページでは、手順を行わずに停止します。ログイン画面で入力した値を、
  別のサイトで入力しないためです。
- 利用者の操作による移動（`cause` が `user`）は、行き先が `origin` か `extraOrigins` のサイトの場合だけ
  実行します。ページの操作による移動（`cause` が `page`）は、移動が終わるのを待つだけで、ページを
  操作しないため、行き先のサイトを問いません。
- PDF の保存（`savePdf`）は、`origin` か `extraOrigins` のサイトのページで行います。

## ファイル

フローを書き出したファイル（管理画面の詳細の［ファイルに書き出し］と、一覧で選んだフローの［書き出し］）は、この形式の JSON です。
1 件の場合はフローのオブジェクト、複数件の場合はフローの配列です。［JSON から追加］では、どちらも
読み込めます。配列は 1 つのファイルで 100 件までです。1 件でも形式に誤りがある場合は、1 件も追加しません。
保存済みのフローと内容が同じフローは追加しません。内容は、`name` と `schemaVersion` を除いたすべての項目
（項目の順序は問いません）で比べます。同じファイルの中で内容が同じフローは、最初の 1 件だけを追加します。

## 手順の種類

### `navigate`：ページの移動

| 項目 | 内容 |
|---|---|
| `url` | 移動先の URL。`https://` または `http://` で始まるものだけです。 |
| `cause` | `user`：利用者の操作による移動（URL の入力、再読み込み、戻る・進む）。`page`：ページの操作による移動（リンク、フォームの送信、転送）。 |
| `dialog` | この手順の後に開いたダイアログへの応答（下記の「ダイアログ」）。省略できます。版 10 で加えました。 |

最初の手順は、記録を始めたページの `navigate`（`cause` は `user`）です。実行時に同じページから始める
ためです。

`cause` が `page` の移動は、直前の手順（クリックなど）の結果として起きたものです。実行時は、この手順で
改めて移動するのではなく、移動が終わるのを待つ手順として扱う想定です。

直前の手順も移動の手順である `cause` が `page` の移動は、ページの読み込みの後にサイトが行った転送です。
ログアウトした状態で記録し、ログイン済みの状態で実行する場合など、実行時にこの転送が起きないことがあります。
実行時は、移動が始まらない状態（ページが変わらず、読み込みが完了していて、次の移動も始まっていない状態）が
5 秒続いたら、転送が起きなかったと判定し、この手順と、続けて記録された転送の手順を飛ばします（#90）。
5 秒の間に移動が始まった場合は、これまでどおり新しいページの読み込みを最大 30 秒待ちます。飛ばした後に実行が
失敗した場合は、止まった理由の最後に、転送を飛ばしたことを加えます。クリックなどの操作の後の移動は、操作が
効かなかった可能性があるため飛ばしません。

同じページの中で URL だけが変わる移動（`history.pushState` など）は記録しません。

### `click`：クリック

| 項目 | 内容 |
|---|---|
| `target` | クリックした要素（下記の「要素の指定」）。 |
| `origin` | 手順を記録したサイトのオリジン。記録を始めたサイト（フローの `origin`）で記録した場合は書きません。`input`、`select`、`extract` の手順も同じです。版 5 で加えました。 |
| `translated` | 記録したときに、ページが Chrome の翻訳で表示されていた場合に `true` です。翻訳していなかった場合は書きません。`input`、`select`、`extract` の手順も同じです。版 8 で加えました（下記の「翻訳したページ」）。 |
| `dialog` | この手順の後に開いたダイアログへの応答（下記の「ダイアログ」）。省略できます。`input`、`select`、`navigate` の手順も同じです。版 10 で加えました。 |
| `download` | クリックでサイトのファイルのダウンロードが始まる場合に、保存先を指定します（下記の「サイトが提供するファイルのダウンロード」）。記録中にクリックの直後にダウンロードが始まった場合は、記録で作られます（#223）。リンクのクリックで PDF などのファイルへ移動した場合は、記録で `from: "link"` の指定が作られます（下記の「リンク先のファイルの保存」）。版 12 で加えました（#20）。 |
| `newTab` | クリックで新しいタブが開く場合に `true` を書きます。以降の手順を、開いたタブで実行します（下記の「`closeTab`」）。記録では作られません。JSON を直接編集して加えます。版 11 で加えました（#20）。 |

リンクやボタンの内側の文字や画像をクリックした場合は、リンクやボタンそのものを記録します。
文字の入力欄と選択肢へのクリックは、入力の準備にすぎないため記録しません。

### `input`：文字の入力

| 項目 | 内容 |
|---|---|
| `target` | 入力した欄。 |
| `value` | 入力した値。入力を終えて欄から離れた時点の値を 1 回だけ記録します。 |
| `secret` | `true` の場合、値を記録していないことを示します。このとき `value` はありません。 |

次の欄の値は記録せず、`secret: true` とします。保存した JSON から漏れることを防ぐためです。

- パスワードの欄（`type="password"`）
- `autocomplete` 属性が `cc-` で始まる欄（クレジットカード番号、有効期限、セキュリティコードなど）
- `autocomplete` 属性が `one-time-code` の欄（確認コード）

対象の入力欄の種類は、`text`、`email`、`search`、`tel`、`url`、`number`、`password`、`date`、`month`、
`week`、`time`、`datetime-local` と `textarea` です。チェックボックスとラジオボタンはクリックとして記録
します。ファイルの選択欄と、`contenteditable` の要素（文書の編集画面など）は記録しません。

### `select`：選択肢の選択

| 項目 | 内容 |
|---|---|
| `target` | 選択肢の要素（`select`）。 |
| `values` | 選んだ選択肢の `value` の一覧。 |
| `labels` | 選んだ選択肢の表示文字列の一覧。 |

複数選択の場合も記録できるよう、どちらも配列です。

実行では、`values` の値と一致する選択肢を選びます。見つからない場合は、`labels` の表示文字列で探します。
ただし、`values` にパラメータの参照（`{{名前}}`）を含む値は、`labels` では探しません。当てはめた値を、選択肢の
`value`、表示文字列の順に照合し、どちらにも一致しない場合は止まります（#216）。`labels` は記録した時点の選択肢の
ため、探すと、入力した値に関係なく記録時の選択肢を選んでしまうためです。例：`{{month.mm}}`（`08`）は、
`value` が `08` の選択肢か、表示文字列が「08」の選択肢を選びます。`value` が `8` で表示文字列が「8」の選択肢には
一致しないため、止まります。その場合は `{{month.month}}` を使います。

### `pause`：一時停止

| 項目 | 内容 |
|---|---|
| `note` | 止まる理由の説明。省略できます。 |

実行はこの手順で一時停止し、止まった理由をサイドパネルに表示します。人が画面を確かめ、必要な操作
（確定など）を行った後、サイドパネルの［再開］を押すと、次の手順から続けます。［実行停止］を押すと、
実行を終了します。30 分間［再開］が押されなかった場合は、実行を終了します。フローの最後の手順の
場合は、続ける手順がないため、一時停止せずに実行を終了します。版 2 で加えました。

一時停止中は、ページを紫の枠で囲み、「⏸ 一時停止中（Lightomate）」と表示します。ツールバーの
アイコンには紫の「WAIT」を表示します。実行中にサイドパネルの［一時停止］を押した場合も、実行中の
手順が終わった時点で、同じ一時停止中の状態になります。

購入や申し込みの確定ボタンは、拡張機能には押させず、人が押します。そのため、次のように扱います。

- 記録中に確定ボタンを押すと、クリックではなく `pause` として記録します。ページにその旨を表示します。
  記録中に押したクリックそのものは止めないため、実際に確定します。
- 実行時は、クリックの手順ごとに、押す直前に要素の文言を確かめます。確定ボタンであれば押さずに
  実行を終了します。JSON を直接編集して加えたクリックの手順にも有効です。この場合は［再開］できません。
  再開すると、確定ボタンを押す手順に進むためです。ページを紫の枠で囲み、「■ 停止：ここから手で
  操作してください（Lightomate）」と表示します。別のページへ移動すると、枠は消えます。

確定ボタンかどうかは、要素の表示文字列、`aria-label`、`title`、`value`、要素の中の画像の `alt` に、
確定を表す語（「注文を確定」「購入する」「Place your order」「Buy now」など）が含まれるかで判定します。
語の一覧は `extension/shared/purchase-guard.js` にあります。

文言は Chrome の翻訳で置き換わるため、翻訳で変わらない手がかりでも判定します（#97）。要素の `id`、`name`、
`class`、`data-testid`、`data-test`、`data-qa`、`formaction`、リンクの `href`、フォームを送信するボタンの
フォームの `action`、手順の `target.selectors` のいずれかに、確定を表す英語の語（`placeorder`、`buynow`、
`submitorder` など）が含まれていれば、確定ボタンと判定します。英数字以外の文字を除いて比べるため、
`place-order`、`place_order`、`placeOrder` はどれも一致します。

画像だけで説明のないボタンや、文言にも属性にも手がかりのないボタンは検出できない場合があります。確定ではないボタンを確定ボタンと判定し、
不要に止まる場合もあります。

文言で判定できないボタンや画面に備え、利用者はフローの管理画面で、サイト（オリジン）ごとに「必ず
止まる場所」を指定できます。指定はフロー定義には含めず、`chrome.storage.local` の `stopRules` に
フローとは別に保存します。そのサイトのすべてのフローに効き、フローの JSON を編集しても外せません。

- 止める要素：CSS セレクター。クリックする要素、またはその祖先の要素が一致した場合に止まります。
- 止める画面：URL のパス。`*` は `/` を含む任意の文字列に一致します。クエリ文字列（`?` 以降）と
  ページ内の位置（`#` 以降）は比べません。表示中のページが一致した場合、クリック・入力・選択を行わずに
  止まります。

記録中は、止める要素に一致するクリックと、止める画面でのクリックを `pause` として記録します。直前の
手順がすでに `pause` の場合は、重ねて記録しません。

### `savePdf`：PDF の保存

表示中のページを PDF にして、Chrome のダウンロード先フォルダーに保存します。版 3 で加えました。
記録では作られません。管理画面の［手順］タブのブロックで加えます（#9）。JSON を直接編集して加えることもできます。

| 項目 | 内容 |
|---|---|
| `path` | 保存先のひな形。ダウンロード先フォルダーからの相対パスで、`/` でフォルダーを区切ります。省略した場合は `Lightomate/{{flow.name}}/{{run.yyyy}}{{run.mm}}{{run.dd}}_{{run.hhmmss}}.pdf` です。末尾が `.pdf` でない場合は `.pdf` を付けます。 |
| `onConflict` | 同じ名前のファイルがある場合の動作。`rename`（既定）は番号を付けて別名で保存し、`overwrite` は上書きします。`overwrite` でも、同じ実行の中ですでに同じ名前で保存した場合は、番号を付けて別名で保存します（#179）。前回までの実行で保存したファイルだけを上書きします。 |
| `mode` | PDF を作るときの表示（#73）。`print`（既定）は印刷用の表示、`screen` は画面の表示で作ります。サイトが印刷用に要素を隠したり配置を変えたりして、画面と異なる PDF になる場合に `screen` を使います。 |

```json
{ "type": "savePdf", "path": "Lightomate/領収書/{{site.host}}/{{month.year}}-{{month.mm}}/{{orderNumber}}.pdf" }
```

`mode` が `screen` の場合も、紙の大きさは印刷用の表示と同じです。紙の幅に合わせて配置し直されるため、
画面とまったく同じにはなりません。画面の上部に固定された見出しは、各ページに写る場合があります。
PDF を作る間は、実行中の枠と文字を隠します。

`mode` は版 3 のまま加えました。`mode` を知らない古い版の拡張機能は、`mode` を無視して印刷用の表示で
保存します。

`path` には、次の値を `{{名前}}` の形で埋め込めます。

| 書き方 | 値 |
|---|---|
| `{{flow.name}}` | フロー名 |
| `{{site.host}}` | フローのサイトのホスト名（例：`www.amazon.co.jp`） |
| `{{run.yyyy}}`、`{{run.mm}}`、`{{run.dd}}` | 実行を始めた年（4 桁）、月（2 桁）、日（2 桁） |
| `{{run.hhmmss}}` | 実行を始めた時刻（例：`070809`） |
| パラメータ | 下記の「パラメータ」と同じ書き方です（例：`{{month}}`、`{{month.mm}}`） |
| 読み取った値 | この手順より前の `extract` で付けた名前（例：`{{orderNumber}}`） |

値を埋め込んだ後の名前は、次のように整えます。値によってダウンロード先フォルダーの外に保存されることを
防ぐためです。処理は `extension/shared/save-path.js` にあります。

- `path` に書いた `/` だけをフォルダーの区切りにします。値の中の `/` と `\` は `_` に置き換えます。
- Windows でファイル名に使えない文字（`\ / : * ? " < > |`）と制御文字は `_` に置き換えます。
- 名前の末尾の空白とドットは取り除きます。空の名前やドットだけの名前（`.`、`..`）は `_` にします。
  Windows の予約名（`CON`、`NUL` など）は先頭に `_` を付けます。
- `path` そのものが絶対パスの場合、空のフォルダー名や `.`、`..` を含む場合は、形式の誤りとして保存できません。

既定では、印刷用の表示（背景の色と画像を含みます）で PDF にします。画面の表示のまま保存する場合は、`mode` に
`screen` を指定します（上の表の `mode`）。
フローのサイトとは別のページを表示している場合は、保存せずに実行を止めます。

### `extract`：ページの文字の読み取り

指定した要素の文字を読み取り、名前を付けて覚えます。後の `savePdf` の `path` で使います。版 3 で加えました。

| 項目 | 内容 |
|---|---|
| `target` | 読み取る要素（下記の「要素の指定」）。 |
| `name` | 読み取った値に付ける名前。英字または `_` で始め、英数字と `_` だけを使います。パラメータと同じ名前、および `flow`、`site`、`run` は使えません。 |
| `notifyOnChange` | `true` の場合は、読み取った値が前回の実行から変わったときに、Chrome の通知で知らせます（下記の「値の変化の通知」）。省略できます。版 19 で加えました（#251）。 |

入力欄と選択肢は、表示している値を読み取ります。それ以外の要素は表示文字列を読み取り、空白をまとめて
1 行にします。200 文字を超える部分は切り捨てます。読み取った文字が空の場合は、実行を止めます。
読み取った値は保存しません。`forEach` の内側で読み取ると、行ごとに値が置き換わります（下記の「`forEach`」）。

#### 値の変化の通知

`notifyOnChange` を `true` にした読み取りは、読み取った値を、次の実行で比べるために覚えます（#251）。定期実行と
組み合わせると、在庫や価格をページで何度も確かめる代わりに、変わったときだけ知らせを受け取れます。

- 初回の実行（覚えた値がない場合）は知らせず、値を覚えるだけです。
- 前回と同じ値の場合は、何もしません。
- 前回と異なる場合は、3 秒待ってから同じ要素を読み直します。2 回とも同じ値だった場合だけ、Windows の通知で
  「「要素の説明」の値が変わりました：前回 … → 今回 …」と知らせ、新しい値を覚えます。Chrome の翻訳は表示の後に
  少し遅れて文字を置き換えるため、置き換えの途中の文字で知らせないようにするためです。読み直した値が 1 回目と
  異なる場合は、知らせず、値も覚えません。次の実行で、もう一度前回の値と比べます。
- 通知を押すと、値を読み取ったページを新しいタブで開きます。
- 値はフローごと、`name` ごとに `chrome.storage.local` に保存します。フローを削除すると、そのフローの値も削除します。
- 繰り返し（`forEach`、`while`）の内側には書けません。値を名前ごとに 1 つだけ覚えるため、行ごとに値が変わると
  比べられないためです。
- 翻訳を有効にしたまま記録・実行するページでは、翻訳された文字を覚えます。翻訳を有効にした状態と無効にした状態を
  切り替えると、値が変わったとして知らせます。

#### サイトが提供するファイルのダウンロード

サイトの［PDF をダウンロード］ボタンなどで保存されるファイルを、指定したフォルダーとファイル名で保存します。
クリックの手順に `download` を書きます。版 12 で加えました（#20）。

| 項目 | 内容 |
|---|---|
| `path` | 保存先のひな形。`savePdf` の `path` と同じ書き方で、同じ値を埋め込めます（下記の「`savePdf`」）。ファイル名がサイトのファイルの拡張子（`.pdf`、`.csv` など）で終わっていない場合は、その拡張子を付けます。省略できません。 |
| `onConflict` | 同じ名前のファイルがある場合の動作。`rename`（既定）は番号を付けて別名で保存し、`overwrite` は上書きします。`overwrite` でも、同じ実行の中ですでに同じ名前で保存した場合は、番号を付けて別名で保存します（#179）。前回までの実行で保存したファイルだけを上書きします。 |
| `from` | `link` の場合は、クリックせずに、要素（リンク）の `href` のファイルを保存します（下記の「リンク先のファイルの保存」）。版 14 で加えました（#172）。 |

```json
{
  "type": "click",
  "target": { "selectors": ["a.invoice-download"], "tag": "a", "label": "PDF をダウンロード", "scope": "item" },
  "download": { "path": "Lightomate/領収書/{{site.host}}/{{month}}/{{orderNumber}}", "onConflict": "overwrite" }
}
```

- クリックの直前から待ち始め、その後に最初に始まったダウンロード 1 件を対象にします。Chrome のダウンロードの
  通知には、どのタブから始まったかが含まれないためです。同じ時間に別のタブでダウンロードを始めると、そのファイルが
  対象になるおそれがあります。実行中は、ほかのダウンロードを始めないでください。
- クリックの後 30 秒以内にダウンロードが始まらない場合は、停止します。ダウンロードが終わるまで（最大 60 秒）
  待ってから、次の手順に進みます。保存したファイルのパスは、実行履歴に残します。
- 1 回のクリックで複数のファイルがダウンロードされる場合は、最初の 1 件だけを対象にします。
- ほかの拡張機能がダウンロードのファイル名を決めている場合は、指定した名前にならないことがあります。その場合も
  停止せず、実際に保存された場所を実行履歴に残します。
- Chrome の設定「ダウンロード前に各ファイルの保存場所を確認する」が有効な場合は、保存の画面が表示される見込みです
  （実際の Chrome では未確認です）。画面を閉じると、保存を取り消したとして停止します。
- `newTab` と同じクリックの手順には書けません。
- 記録中に、クリックから 10 秒以内に、そのページのサイトのファイル（ダウンロードの URL か参照元がそのサイトのもの）の
  ダウンロードが始まった場合は、そのクリックに `download` を付けて記録します（#223）。保存先は
  `Lightomate/{{flow.name}}/{{run.yyyy}}{{run.mm}}{{run.dd}}_{{run.hhmmss}}` です。記録中のダウンロードそのものは、
  Chrome の通常のダウンロードのまま保存されます。ほかの拡張機能が始めたダウンロードと、`data:` の URL で参照元のない
  ダウンロードは、クリックに結び付けません。

#### リンク先のファイルの保存

PDF などのファイルを開くリンクで、Chrome がファイルを表示画面で開いてしまい、保存されない場合に使います。
`download` に `"from": "link"` を書くと、クリックせずに、要素（リンク）の `href` のファイルを保存します。
版 14 で加えました（#172）。

```json
{
  "type": "click",
  "target": { "selectors": ["a.invoice"], "tag": "a", "label": "明細書", "scope": "item" },
  "download": { "path": "Lightomate/領収書/{{site.host}}/{{month}}/{{orderNumber}}", "onConflict": "overwrite", "from": "link" }
}
```

- 保存するのは、フローのサイト（`origin`、`extraOrigins`）の `http`・`https` の URL だけです。リンクが別のサイトを
  指す場合は、保存せずに停止します。
- サイトの Cookie（ログインの状態）を付けて取得します。
- 要素がリンク（`href` を持つ `a`）でない場合は停止します。
- ページを移動しないため、PDF の表示画面は開きません。繰り返しの中では、一覧のページに留まったまま次の行へ進みます。
- 記録中に、リンクのクリックの直後に、URL のパスが `.pdf`、`.csv`、`.zip`、`.xlsx`、`.xls`、`.docx`、`.doc` で
  終わるページへ移動した場合は、移動を記録せず、そのクリックをこの指定に変えます。保存先は
  `Lightomate/{{flow.name}}/{{run.yyyy}}{{run.mm}}{{run.dd}}_{{run.hhmmss}}`、`onConflict` は `rename` です。
  保存先は、保存した後に編集画面で変えられます。
- 記録で変える場合は、押したリンクの `href` から、同じ種類のリンクを探すセレクターを作り、`selectors` の先頭に
  加えます。あわせて `all` を `true` にします（#185、下記の「一致するリンクをすべて保存する」）。

##### 一致するリンクをすべて保存する

`download` に `"all": true` を書くと、要素の指定に一致する、表示されているリンクのファイルをすべて保存します。
`from` が `link` の場合にだけ書けます。版 16 で加えました（#185）。明細書が複数ある注文（「明細書／適格請求書 1」
「明細書／適格請求書 2」など）で、すべての明細書を保存するために使います。

```json
{
  "type": "click",
  "target": {
    "selectors": ["a[href*=\"/documents/download/\"][href*=\"/invoice.pdf\"]"],
    "tag": "a",
    "label": "明細書／適格請求書"
  },
  "download": { "path": "Lightomate/領収書/{{orderNumber}}", "onConflict": "overwrite", "from": "link", "all": true }
}
```

- 探すのは、最初に表示中の要素が見つかったセレクターに一致する、表示されているリンクです。隠れている要素
  （前に開いて閉じた小さな枠の中のリンクなど）は含めません。同じリンク先は 1 回だけ保存します。
- 1 件目は `path` の名前で保存します。2 件目以降は、名前の末尾（拡張子を書いた場合はその前）に `_2`、`_3` … を
  付けます。例：`Lightomate/領収書/503-1.pdf`、`Lightomate/領収書/503-1_2.pdf`。もう一度実行しても同じ名前に
  なるため、`onConflict` が `overwrite` の場合は、同じファイルが増えません。
- 一致するリンクが 10 件を超える場合は、意図しないリンクにも一致している可能性があるため、保存せずに停止します。
- 記録で作るセレクターは、`href` のパスから、注文ごとに変わる部分（3 桁以上の数字か、8 文字以上の 16 進数を含む
  区切り）を除いた前後の部分を含むリンクに一致します。例：`/documents/download/<ID>/invoice.pdf` から
  `a[href*="/documents/download/"][href*="/invoice.pdf"]`。表示の文字を使わないため、翻訳しても、明細書の数で
  リンクの文字が変わっても見つかります。変わらない部分が短すぎる場合は作らず、`all` も書きません。

### `closeTab`：タブを閉じて元のタブに戻る

`newTab` を付けたクリックで開いたタブを閉じ、開く前のタブに戻ります。以降の手順は、元のタブで実行します。
版 11 で加えました（#20）。記録では作られません。JSON を直接編集して加えます。項目は `type` だけです。

```json
{ "type": "click", "target": { "selectors": ["a.receipt"], "tag": "a", "label": "領収書", "scope": "item" }, "newTab": true },
{ "type": "savePdf", "path": "Lightomate/領収書/{{orderNumber}}.pdf", "onConflict": "overwrite" },
{ "type": "closeTab" }
```

- `newTab` を付けたクリックの後は、そのクリックで開いたタブ（Chrome が、元のタブから開いたとして扱うタブ）を
  30 秒まで待ちます。開かない場合は停止します。リンクの `target="_blank"` のほか、ページのスクリプトが
  クリックに応じて開くタブ（`window.open`）も対象です。
- 開いたタブの読み込みが終わってから、次の手順を行います。続けて「ページの操作による移動」（`navigate`、
  `cause` が `page`）の手順がある場合は、開いたタブの読み込み済みのページを移動先として扱います。
- 開いたタブでも、手順を記録したサイトのページでだけ操作します（#41）。確定ボタンの手前で止める確認も、
  元のタブと同じく行います。
- 開いたタブの中で、さらに新しいタブを開くことはできません。停止します。
- `closeTab` の前に、`newTab` を付けたクリックがない場合は停止します。
- `closeTab` を書かずにフローが終わった場合は、開いたタブを閉じずに残します。
- 実行中に利用者が開いたタブを閉じた場合は、停止します。
- `forEach` の行の中でタブを開いた場合は、その行の手順の最後までに `closeTab` を書きます。閉じないまま
  次の行へ進もうとした場合は、停止します。`closeTab` で元のタブに戻ると、一覧のページは移動していない
  ため、開き直さずに次の行へ進みます。

### `wait`：待機

指定した時間だけ待ってから、次の手順に進みます。版 4 で加えました。ページの移動の後や、表示の遅いページで
使います。記録では作られません。管理画面の［手順］タブのブロックで加えます（#9）。JSON を直接編集して加えることもできます。

| 項目 | 内容 |
|---|---|
| `ms` | 待つ時間（ミリ秒）。1 以上 300,000（5 分）以下の整数です。 |

```json
{ "type": "wait", "ms": 3000 }
```

待っている間も、サイドパネルの［停止］で実行を止められます。

### `if`：条件分岐

条件を満たすかで、行う手順を分けます。版 6 で加えました。記録では作られません。管理画面の［手順］タブのブロックで
加え、対象の要素はページの上で選びます（#139）。JSON を直接編集して加えることもできます。

| 項目 | 内容 |
|---|---|
| `condition` | 条件（下記の「条件」）。 |
| `then` | 条件を満たす場合に行う手順の一覧。 |
| `else` | 条件を満たさない場合に行う手順の一覧。省略できます。 |

```json
{
  "type": "if",
  "condition": {
    "target": { "selectors": ["#ap_email"], "tag": "input", "label": "メールアドレス" },
    "exists": true
  },
  "then": [
    { "type": "input", "target": { "selectors": ["#ap_email"], "tag": "input", "label": "メールアドレス" }, "value": "taro@example.com" }
  ]
}
```

- `then` と `else` の中には、ページの移動を含むすべての種類の手順を書けます。

### 条件

`if` と `while` の `condition` には、`target`（調べる要素、下記の「要素の指定」）と、次のどれか 1 種類を書きます。

| 種類 | 項目 | 内容 |
|---|---|---|
| 要素の有無 | `exists` | `true` の場合は要素があること、`false` の場合は要素がないことを条件にします。 |
| 文字 | `contains` | 要素の表示の文字が、この文字を含むことを条件にします。版 9 で加えました。 |
| 文字 | `equals` | 要素の表示の文字が、この文字と一致することを条件にします。版 9 で加えました。 |
| 日付 | `month` | 要素の表示の文字から読み取った日付が、この月（`2026-09` の形式）に含まれることを条件にします。版 9 で加えました。 |
| 日付 | `before` | 読み取った日付が、この月（`2026-09` の形式）の 1 日より前であることを条件にします。新しい順に並んだ一覧で、対象月より古い行に達したことを判定するために使います（下記の「`break`」）。版 13 で加えました（#162）。 |
| 日付 | `from`、`to` | 読み取った日付が、この期間（`2026-09-01` の形式、両端を含みます）に含まれることを条件にします。片方だけも書けます。版 9 で加えました。 |

```json
{
  "type": "if",
  "condition": {
    "target": { "selectors": [".order-date"], "tag": "span", "label": "注文日", "scope": "item" },
    "month": "{{month}}"
  },
  "then": [
    { "type": "click", "target": { "selectors": ["a.receipt"], "tag": "a", "label": "領収書", "scope": "item" } }
  ]
}
```

- 文字と日付の値には、パラメータの参照（`{{名前}}`）を書けます。年月のパラメータ（`month`）を `{{month}}`
  と書くと、`2026-09` の形式の値になります。
- 文字は、前後の空白を除き、続く空白を 1 つにしてから比べます。大文字と小文字は区別します。
- 調べるのは、フローのサイト（`origin` と `extraOrigins`）のページだけです。別のサイトのページでは停止します。
- 要素を調べるだけで、ページは操作しません。ログインや認証の画面かどうかの確認（#18）も行いません。
  「ログインの画面が表示されたときだけ入力する」という条件にも使えるようにするためです。
- 要素の有無の条件で、要素がすぐに見つからない場合は、3 秒まで待ってから判定します。表示の遅い要素を
  「ない」と判定しないためです。そのため、要素がない場合は判定に 3 秒かかります。
- 文字と日付の条件で要素が見つからない場合は、「条件を満たさない」とは扱わず、停止します。表示の遅れで
  誤った分岐に進まないためです。

#### 翻訳したページでの条件

Chrome の翻訳で表示の文字が置き換わると、文字の条件の結果が逆になり、`then` と `else` のどちらを行うかも
入れ替わります。どちらの分岐が安全かはフローによって異なるため、**文字の条件は、ページが翻訳されている場合は
判定せずに停止します**。翻訳されているかは、「翻訳したページ」の節と同じ方法で判定します。

日付の条件は、下記の表記の日付として読めた場合だけ判定します。翻訳で表記が変わっても（例：
`September 1, 2026` が `2026年9月1日` になっても）、同じ日付として読めれば結果は変わらないため、翻訳された
ページでも判定します。

#### 日付の読み取り方

年・月・日の並びが一意に決まる、次の表記だけを読みます。

- `2026年9月1日`
- `2026/9/1`、`2026/09/01`、`2026-09-01`、`2026.9.1`（区切りの文字は揃っている必要があります）
- `September 1, 2026`、`Sep 1, 2026`、`1 September 2026`（英語の月名と、その略記）

次の場合は、判定せずに停止します。

- 日付が 1 つもない場合
- 異なる日付が 2 つ以上ある場合（同じ日付が複数の表記で書かれている場合は、1 つとして扱います）
- 存在しない日付（`2026年2月30日` など）がある場合
- `9/1/2026` のように、月と日の順序が決まらない表記がある場合

### `forEach`：繰り返し

一覧の各行で、同じ手順を行います。版 6 で加えました。管理画面の［手順］タブのブロックで加え、対象の要素は
ページの上で選びます（#139）。記録した手順の範囲を、サイドパネルの［繰り返しにする］で変えて作ることもできます
（#167）。JSON を直接編集して加えることもできます。

| 項目 | 内容 |
|---|---|
| `items` | 一覧の各行を指す要素の指定（下記の「要素の指定」）。`selectors` には、すべての行に一致するセレクターを書きます（例：`tr.order-row`）。 |
| `max` | 繰り返しの上限。1 以上 500 以下の整数です。省略した場合は 100 です。ページ送りを使う場合は、全ページの行の合計の上限です。 |
| `nextPage` | 次のページへ送る要素（「次へ」のボタンやリンク）の指定。省略できます。書いた場合は、ページの行をすべて処理した後にこの要素をクリックし、次のページの行を続けて処理します（下記の「ページ送り」）。版 7 で加えました。 |
| `maxPages` | ページ送りの上限。1 以上 50 以下の整数です。省略した場合は 10 です。版 7 で加えました。 |
| `onMissing` | 行の中で要素（`scope: item`）が見つからない場合の動作です。`stop`（既定）は実行を止めます。`skip` は、その行の残りの手順を行わずに次の行へ進みます（下記の「要素がない行を飛ばす」）。版 15 で加えました（#174）。 |
| `steps` | 各行で行う手順の一覧。 |

```json
{
  "type": "forEach",
  "items": { "selectors": ["tr.order-row"], "tag": "tr", "label": "注文の行" },
  "steps": [
    { "type": "extract", "target": { "selectors": [".order-number"], "tag": "span", "label": "注文番号", "scope": "item" }, "name": "orderNumber" },
    { "type": "click", "target": { "selectors": ["button.detail"], "tag": "button", "label": "詳細", "scope": "item" } }
  ]
}
```

- 行は、`selectors` を順に試し、表示されている要素が 1 つ以上見つかった最初のセレクターの、表示されている
  要素をすべて使います。`text` による手がかりは使いません。
- 行数は、繰り返しを始めた時点で数えます。行が見つからない場合は、3 秒まで待ってから 0 件と判定し、内側の
  手順を行わずに次の手順へ進みます。
- 行数が `max` を超える場合は、繰り返しを始めずに停止します。一部の行だけを処理して、残りを見落とすことを
  防ぐためです。
- 各回は、その番号の行をページから探し直します。途中で行が見つからなくなった場合（行が消えた場合など）は、
  2 回までやり直した後、停止します。
- 内側の手順で `target` に `"scope": "item"` を書くと、その行の内側だけで要素を探します（下記の「要素の指定」）。
  書かない場合は、これまでどおりページ全体で探します。
- 内側には、ページの操作による移動（`navigate`、`cause` が `page`）の手順を書けます（版 7 から）。利用者の
  操作による移動（`cause` が `user`）は書けません。一覧のページへは、次の「行の中でのページの移動」のとおり
  自動で戻るためです。
- 内側の `extract` で付けた名前の値は、行ごとに置き換わります。行ごとに別の名前の PDF を保存できます。

#### 要素がない行を飛ばす

キャンセル済みの注文のように、一部の行に要素（［領収書等］のリンクなど）がない一覧で使います（#174）。
`"onMissing": "skip"` の繰り返しでは、行の中の要素（`scope: item`）が見つからない場合に、その行の残りの手順を
行わずに次の行へ進みます。管理画面のブロックでは、繰り返しのブロックの「要素がない行は飛ばす」の欄です。
サイドパネルの［繰り返しにする］（#167）で作った繰り返しは、既定でこの指定になります。

- 飛ばした行は、サイドパネルの実行のカードと実行履歴に「要素が見つからない 2 件の行を飛ばしました：10 件目
  （クリック：領収書等）、…」の形で残します。行の内容（注文番号など）は残しません。
- 飛ばすのは、行の中の要素が見つからない場合だけです。ページ全体で探す要素が見つからない場合と、ほかの誤り
  （別のサイトへの移動、確定ボタンの手前など）では、今までどおり止めます。ページの構造が変わった場合に、
  すべての行を気付かないまま飛ばさないためです。
- 行の中の要素は、やり直さずに 1 回だけ探します（10 秒まで待ちます）。
- 繰り返しのすべての行を飛ばした場合は、「失敗」にします。行の中の要素の指定が誤っているおそれがあるためです。

#### 行の中でのページの移動

版 7 から、行のリンクをクリックして詳細のページへ移動し、読み取りや PDF の保存を行えます（#95）。

```json
{
  "type": "forEach",
  "items": { "selectors": ["tr.order-row"], "tag": "tr", "label": "注文の行" },
  "steps": [
    { "type": "extract", "target": { "selectors": [".order-number"], "tag": "span", "label": "注文番号", "scope": "item" }, "name": "orderNumber" },
    { "type": "click", "target": { "selectors": ["a.receipt"], "tag": "a", "label": "領収書", "scope": "item" } },
    { "type": "navigate", "cause": "page", "url": "https://www.example.com/receipt" },
    { "type": "savePdf", "path": "Lightomate/領収書/{{orderNumber}}.pdf", "onConflict": "overwrite" }
  ]
}
```

- 行数を数えたときのページの URL を控えます。行の手順を終えた時点で、表示中のページが行数を数えたときと
  異なる場合は、その URL を開き直して一覧のページへ戻ってから、次の行へ進みます。最後の行の後も、一覧の
  ページへ戻ってから繰り返しを終えます。
- 戻った後は行数を数え直し、1 行目の目印も比べます。どちらかが最初と異なる場合は、停止します。前の行の
  番号で、別の行を操作しないためです。目印は、行の中のリンク先（`href` の値）です。リンクがない行では、
  画像の `src` の値です。どちらもない行では、行数だけで確かめます。ほかの行にない、その行に固有のリンク先がある
  場合は、その中の 1 件以上が一致すれば同じ行とみなします（#177）。読み込むたびに値が変わるリンク（ダウンロードの
  URL など）があっても、注文の詳細へのリンクなどが一致すれば止まりません。表示の文字は使いません。Chrome の翻訳などが
  表示の後に文字を置き換え、同じ一覧でも読み取った時点によって文字が異なるためです。フォームの送信で表示した一覧や、ページを読み込まずに一覧だけを
  差し替えるページ送りなど、URL を開き直しても同じ一覧が表示されないページでは、ここで停止します。
- 戻った先がログインの画面などの場合は、一時停止します。ログインを済ませて［再開］を押すと、もう一度一覧の
  ページへ戻ります。
- 行の操作で新しいタブが開く場合は、クリックの手順に `newTab` を付け、行の手順の最後に `closeTab` を書きます（上記の「`closeTab`」）。

#### ページ送り

`nextPage` を書くと、一覧が複数のページに分かれている場合に、最後のページまで同じ手順を行います（#95）。

```json
{
  "type": "forEach",
  "items": { "selectors": ["tr.order-row"], "tag": "tr", "label": "注文の行" },
  "nextPage": { "selectors": ["a.next:not(.disabled)"], "tag": "a", "label": "次へ" },
  "maxPages": 12,
  "steps": [
    { "type": "extract", "target": { "selectors": [".order-number"], "tag": "span", "label": "注文番号", "scope": "item" }, "name": "orderNumber" }
  ]
}
```

- ページの行をすべて処理した後に、`nextPage` の要素をページ全体から探します。見つからない場合は、最後の
  ページとして繰り返しを終えます。最後のページで見つからないことは正常なため、やり直しはしません。
- 見つかった場合は、その要素をクリックします。クリックの前には、ほかのクリックと同じ確認（手順を記録した
  サイトのページか、確定ボタンではないか）を行います。
- クリックの後は、新しいページが読み込まれるか、ページを読み込まずに一覧だけが差し替わる（1 行目の目印が
  変わる）まで、最大 30 秒待ちます。どちらも起きない場合は停止します。一覧だけを差し替えるサイトで、行の中に
  リンクも画像もない場合は、差し替わったことを判定できないため停止します。最後のページで押せない状態の
  「次へ」が残るサイトでは、`selectors` を押せる「次へ」にだけ一致させてください（例：`a.next:not(.disabled)`）。
- 次のページの行数を数え、その 1 行目から続けます。0 件の場合は繰り返しを終えます。
- 次のページがあるのに `maxPages` に達した場合と、全ページの行の合計が `max` を超える場合は、停止します。
  上限で黙って終えると、処理していない行があることに気付けないためです。
- ［繰り返しにする］で、記録中に押した「次へ」を選んだ場合は、`nextPage` の `selectors` に、ページ番号の数で
  位置が変わらない指定（class を使う指定、`rel="next"`、最後の項目をたどる指定）だけを書きます（#182）。
  何番目の要素かをたどる指定と、表示の文字（`text`）は書きません。`maxPages` は書かず、既定の 10 になります。
- `nextPage` と `maxPages` は、外側に `forEach` がない `forEach` にだけ書けます。内側の繰り返しでページを
  送ると、外側の行の番号が意味を失うためです。`nextPage` に `scope` は書けません。
- サイドパネルと実行履歴では、何ページ目かを添えます（例：「手順 5 / 12（2 ページ目の 3 件目）」）。

### `while`：条件を満たす間の繰り返し

条件を満たす間、同じ手順を繰り返します。版 9 で加えました（#103）。記録では作られません。JSON を直接
編集して加えます。

| 項目 | 内容 |
|---|---|
| `condition` | 条件（上記の「条件」）。`if` と同じ書き方です。 |
| `max` | 繰り返しの上限。1 以上 500 以下の整数です。省略した場合は 100 です。 |
| `steps` | 繰り返す手順の一覧。 |

```json
{
  "type": "while",
  "condition": {
    "target": { "selectors": ["button.more"], "tag": "button", "label": "もっと見る" },
    "exists": true
  },
  "max": 20,
  "steps": [
    { "type": "click", "target": { "selectors": ["button.more"], "tag": "button", "label": "もっと見る" } },
    { "type": "wait", "ms": 1000 }
  ]
}
```

- 繰り返しの各回の初めに、その時点のページで条件を判定します。初めから条件を満たさない場合は、`steps` を
  行わずに次の手順へ進みます。
- **上限の回数を終えても条件を満たしている場合は、停止します。** `forEach` の `max` は処理する件数の上限の
  ため、上限で止めずに次の手順へ進みます。これに対し `while` は「条件がなくなるまで」の繰り返しのため、上限に
  達したことは想定外の状態として扱います。
- `steps` の中には、ページの移動を含むすべての種類の手順を書けます。
- `forEach` の内側の `while` では、条件と手順の `target` に `"scope": "item"` を書けます。処理中の行の内側で
  探します。
- サイドパネルと実行履歴では、何回目かを添えます（例：「手順 4 / 9（3 回目）」）。

### `break`：繰り返しを終える

この手順を囲む最も内側の `forEach` か `while` を終え、その繰り返しの次の手順へ進みます。版 13 で加えました（#162）。
記録では作られません。管理画面の［手順］タブのブロック（［この繰り返しを終える］）で加えます。JSON を直接編集して
加えることもできます。項目は `type` だけです。

新しい順に並んだ購入履歴で、対象月より古い注文に達した時点で処理を終える場合に使います。残りの行と、次のページを
開かずに終えるため、ページ送りの上限（`maxPages`）に達して停止することもありません。

```json
{
  "type": "forEach",
  "items": { "selectors": ["tr.order-row"], "tag": "tr", "label": "注文の行" },
  "nextPage": { "selectors": ["a.next:not(.disabled)"], "tag": "a", "label": "次へ" },
  "steps": [
    {
      "type": "if",
      "condition": {
        "target": { "selectors": [".order-date"], "tag": "span", "label": "注文日", "scope": "item" },
        "before": "{{month}}"
      },
      "then": [{ "type": "break" }]
    }
  ]
}
```

- `break` は、`forEach` か `while` の内側（その中の `if` の `then`、`else` を含みます）にだけ書けます。外側に
  繰り返しがない場合は、形式の誤りです。
- 繰り返しが入れ子の場合は、最も内側の繰り返しだけを終えます。
- 繰り返しを終えた時点のページのまま、次の手順へ進みます。`forEach` の行の中で詳細のページへ移動していても、
  一覧のページへは戻りません。
- 行の中で `newTab` を付けたクリックで開いたタブを閉じないまま `break` に達した場合は、停止します。`break` の前に
  `closeTab` を書きます。
- 一覧が新しい順に並んでいない場合、`break` を使うと、対象月の注文を処理しないまま終えることがあります。一覧の
  並び順を確かめてから使います。

### 入れ子と手順の番号

- `if`、`forEach`、`while` は、互いに入れ子にできます。入れ子は 3 段までです。
- 入れ子の `forEach` の `items` に `"scope": "item"` を書くと、外側の行の内側で行を探します。
- サイドパネル、管理画面、実行履歴の手順の番号は、入れ子を展開した通し番号です。親の手順、`then`、`else`、
  `forEach` と `while` の内側の順に数えます。繰り返しの中では、何件目の行かを添えます（例：「手順 5 / 12（3 件目）」）。
- 値を記録していない入力欄（`secret`）の値も、この通し番号で入力します。`forEach` の内側の場合は、同じ値を
  すべての行で入力します。

## 手順の間隔（`interval`）

手順と手順の間に待つ時間の範囲です。版 4 で加えました。各手順の後に、`min` と `max` の間（両端を含む）から
毎回ランダムに決めた時間だけ待ちます。最後の手順の後には待ちません。管理画面のフローの詳細の
「実行速度」でも設定できます（画面では秒で入力します）。

| 項目 | 内容 |
|---|---|
| `min` | 最短の時間（ミリ秒）。1,000（1 秒）以上 60,000（60 秒）以下の整数です。 |
| `max` | 最長の時間（ミリ秒）。`min` 以上 60,000 以下の整数です。`min` と同じ場合は一定の間隔です。 |

下限の 1,000 ミリ秒は、間隔を短くしすぎて、自動操作と判断されることを防ぐためのものです（#110）。
1,000 未満の値を含むフローは、保存とファイルからの読み込みで誤りになります。下限を設ける前に保存した
フローで、値が 1,000 未満のものは、保存した値を書き換えずに、実行時に 1,000 ミリ秒として待ちます。

```json
"interval": { "min": 1000, "max": 3000 }
```

省略した場合は、`{ "min": 1000, "max": 1000 }`（1 秒）です。要素が表示されるまで待つ処理と、ページの
読み込みを待つ処理は、この間隔とは別に行います。

速度の制御は、サイトへの負荷と、自動操作と判断されてアカウントが制限される可能性を下げるための対策です。
利用規約の遵守を意味しません。規約が自動操作そのものを禁止しているサイトでは、速度を落としても規約違反で
あることは変わりません。

## パラメータ（`params`）

実行のたびに変わる値（検索語、サイズ、対象月など）を定義します。実行するとき、サイドパネルに
パラメータごとの入力欄を表示し、入力した値を手順に当てはめます。入力した値は保存しません。

```json
"params": [
  { "name": "keyword", "label": "検索語", "type": "text" },
  { "name": "size", "label": "サイズ", "type": "select", "options": ["S", "M", "L"], "default": "M" },
  { "name": "target", "label": "対象月", "type": "month", "default": "@previous-month" }
]
```

| 項目 | 内容 |
|---|---|
| `name` | 名前。英字または `_` で始め、英数字と `_` だけを使います。同じ名前は使えません。 |
| `label` | 入力欄に表示する説明。 |
| `type` | 種類。`text`（文字列）、`number`（数値）、`select`（選択肢）、`month`（年月）のいずれかです。 |
| `options` | 選択肢の一覧。`type` が `select` の場合に必須です。 |
| `default` | 既定値。省略できます。年月では `@current-month`（今月）、`@previous-month`（前月）、`@month-before-last`（前々月、#163）も使えます。実行した日から計算します。 |

入力欄を空にした場合は既定値を使います。既定値もない場合は実行できません。

### 手順での使い方

手順の次の値の中に `{{名前}}` と書くと、実行時に入力した値に置き換えます。

- `input` の `value`
- `select` の `values`
- `navigate` の `url`

年月のパラメータでは、次の書き方も使えます。対象月が 2026 年 8 月の場合の例です。

| 書き方 | 値 |
|---|---|
| `{{target}}` | `2026-08` |
| `{{target.year}}` | `2026` |
| `{{target.month}}` | `8` |
| `{{target.mm}}` | `08` |

定義していない名前を参照すると、形式の誤りとして保存できません。`navigate` の `url` に値を当てはめた
結果が、`origin` とは別のサイトになる場合は実行しません。

### 値を記録していない入力欄

`secret: true` の入力欄（パスワードなど）は、実行するときに入力欄を自動で追加します。パラメータとして
定義する必要はありません。入力した値は保存しません。

## 翻訳したページ

Chrome の翻訳は、表示の文字を置き換えます。要素の指定の `text` と、選択肢の `labels` は表示の文字のため、
記録時と実行時で翻訳の有無が異なると一致せず、要素や選択肢が見つからずに止まる場合があります（#99）。

記録時には、ページが翻訳されていたかを手順の `translated` に残します。翻訳されていたかは、ページの `html`
要素に `translated-ltr` か `translated-rtl` の class があるかで判定します。Chrome の翻訳が付ける印です。

実行時に要素や選択肢が見つからずに止まった場合は、実行時のページが翻訳されているかを調べ、止まった理由に
次の説明を加えます。操作するかどうかの判定には使いません。

| 記録時 | 実行時 | 止まった理由に加える説明 |
|---|---|---|
| 翻訳していない | 翻訳している | 翻訳の有無が異なることと、原文の表示に戻して実行し直す案内 |
| 翻訳している | 翻訳していない | 翻訳の有無が異なることと、ページを翻訳して実行し直す案内 |
| 不明（版 7 以前のフロー） | 翻訳している | 翻訳が原因で見つからない場合があることと、原文の表示に戻して実行し直す案内 |
| 実行時と同じ | | なし |

ただし、要素の指定に翻訳で変わる手がかりがない場合は、説明を加えません（#206）。翻訳で変わる手がかりは、
`text`、翻訳で変わる属性（`title`、`alt`、`placeholder`、`aria-label`、`value`）を参照するセレクター（部品の
`shadow` を含みます）、選択肢の選択（`select`）の `labels` です。`id` や `name` だけで指定した要素は、翻訳しても
見つかり方が変わらないため、翻訳をやめても結果は同じです。

## ダイアログ

サイトは、`alert`（知らせ）、`confirm`（確認）、`prompt`（文字の入力）のダイアログと、ページを離れるときの
確認を表示することがあります。ダイアログが開いている間は、閉じるまでページのスクリプトがすべて止まります（#88）。

実行中は、実行を始めた時点から `chrome.debugger` で実行中のタブに接続し、開いたダイアログを受け取ります。
ダイアログが開いた後に接続しても応答できないためです。接続している間、Chrome は画面の上部に、拡張機能が
デバッグを開始した旨を表示します。この表示で［キャンセル］を押すと、ダイアログに応答できなくなるため、実行を
停止します。

クリック・入力・選択・移動の手順の `dialog` に、その手順の後に開いたダイアログへの応答を、開いた順に書きます。
記録では作られません。JSON を直接編集して書きます。

| 値 | 応答 |
|---|---|
| `"accept"` | ［OK］を押します。ページを離れるときの確認では、ページを離れます。 |
| `"dismiss"` | ［キャンセル］を押します。ページを離れるときの確認では、ページにとどまります。 |

`"accept"` か `"dismiss"` を 1〜5 個並べた配列です。例：確認に［OK］を返し、続けて開く知らせを閉じる場合は
`"dialog": ["accept", "accept"]` と書きます。

```json
{ "type": "click", "target": { "selectors": ["#cancel"], "tag": "button", "label": "取り消す" }, "dialog": ["accept"] }
```

- **対象の範囲**：手順がページの操作を始めてから、次のクリック・入力・選択・移動の手順がページの操作を始める
  までに開いたダイアログです。移動の手順では、移動の前のページが表示するページを離れるときの確認も含みます。
- **一時停止する場合**：`dialog` がない場合、書いた数を超えてダイアログが開いた場合、`prompt` のダイアログの
  場合は、応答せずに一時停止します。止まった理由には、ダイアログの種類と文言（先頭 200 文字まで）を表示します。
  利用者がダイアログに応答してから［再開］を押すと、続きを行います。一時停止中に利用者の操作で開いたダイアログには
  応答しません。
- **実行を終える場合**：確認とページを離れるときの確認に `"accept"` を書いていても、文言に確定を表す語（「注文を
  確定」など、確定ボタンの判定と同じ語）がある場合は応答せず、確定ボタンの手前と同じく実行を終えます。確定は
  人が行うためです。ダイアログは開いたまま残り、利用者が応答します。
- **停止する場合**：ダイアログが開いている間に［実行停止］を押すと、［キャンセル］で閉じてから停止します。
- ダイアログの文言は、ページの表示の文字ではないため、Chrome の翻訳では置き換わらないと考えています（確かめて
  いません）。確定を表す語の判定は、置き換わった場合も止まる側に誤ります。

## 要素の指定（`target`）

| 項目 | 内容 |
|---|---|
| `selectors` | 要素を見つけるための CSS セレクター。優先する順に並びます。1 つ以上あります。 |
| `tag` | 要素のタグ名（小文字）。 |
| `label` | 人が読むための説明。`aria-label`、対応する `label` 要素の文字、表示文字列、`placeholder`、`title`、`name`、`id` の順に、最初に見つかったものです。どれもない場合はタグ名です。 |
| `text` | 要素の表示文字列（100 文字まで）。ボタンやリンクにあり、入力欄にはありません。ボタンとして表示される `input` 要素では `value`（画像の場合は `alt`）です。 |
| `scope` | `item` を書くと、ページ全体ではなく、`forEach` で処理中の行の内側だけで要素を探します。`forEach` の内側の手順にだけ書けます。省略できます。版 6 で加えました。 |
| `shadow` | 要素が Shadow DOM（部品の中身を外から隠す仕組み）の中にある場合の、外側の部品を指すセレクターの一覧です。最も外側の部品から順に並べます（下記の「Shadow DOM の中の要素」）。1〜10 個です。`forEach` の `items` と `nextPage` には書けません。省略できます。版 17 で加えました（#20）。 |
| `frame` | 要素が iframe（ページの中に埋め込まれた別のページ）の中にある場合の、その iframe の指定です（下記の「iframe の中の要素」）。`forEach` の `items` と `nextPage` には書けず、`scope` とも同時に書けません。省略できます。版 18 で加えました（#20）。 |

`selectors` は、ページの構造が変わっても同じ要素を指しやすい順に並べます。

1. `id`（自動で生成されたとみられるものは除きます。例：`ember123`、`react-select-3-input`）
2. `data-testid`、`data-test`、`data-qa`、`name`、`aria-label`、`placeholder` の属性
3. 何番目の要素かをたどる指定（例：`#main > div:nth-of-type(2) > button`）

1 と 2 は、記録した時点でページ内のその要素だけを指すものだけを残します。3 は常に最後に 1 つ入ります。

### Shadow DOM の中の要素

Shadow DOM は、部品の中身を外から隠す仕組みです。入力欄やボタンを部品として作っているサイトで使われています。
ページのスクリプトからも中が見えない種類（閉じた Shadow DOM）も扱えます。記録した要素が Shadow DOM の中に
ある場合は、`shadow` に外側の部品を指すセレクターを並べます。

```json
{
  "type": "click",
  "target": {
    "selectors": ["button.submit", "button:nth-of-type(2)"],
    "tag": "button",
    "label": "送信",
    "shadow": ["checkout-form", "#payment"]
  }
}
```

- 実行では、`shadow` の順に部品の内側へ入り、最も内側の部品の中で `selectors` と `text` を使って要素を探します。
  `scope` が `item` の場合は、処理中の行の内側から部品を探します。
- 部品のセレクターは、`id`、`data-testid`、`data-test`、`data-qa`、`name` の属性、独自の部品のタグ名（`-` を含む
  タグ名）、何番目の要素かをたどる指定の順に、最初に 1 つの部品だけを指すものを 1 つ選びます。Chrome の翻訳で
  置き換わる文字の属性（`aria-label` など）は使いません。
- `selectors` は、部品の内側で 1 つの要素だけを指すものを残します。何番目の要素かをたどる指定は、部品の内側の
  最も外側の要素から始まります。
- 一致する部品が複数ある場合は、Shadow DOM を持つ最初の部品を使います。
- 部品が見つからない場合は、要素と同じく待つ上限の時間まで待ち、見つからない部品のセレクターを示して停止します。
- Shadow DOM の中の要素は、［繰り返しにする］の一覧の行と「次へ」の候補になりません。一覧の行と「次へ」は
  ページ全体で探すためです。
- 入力欄やボタンなど、ブラウザーが内部に持つ部品の内側は対象にしません。

### iframe の中の要素

iframe は、ページの中に別のページを埋め込む仕組みです。決済の入力欄や、外部のサービスの画面でよく使われます。
記録した要素が iframe の中にある場合は、`frame` にその iframe の中のページの URL を書きます。

```json
{
  "type": "input",
  "target": {
    "selectors": ["input[name=\"cardnumber\"]"],
    "tag": "input",
    "label": "カード番号",
    "frame": { "url": "https://pay.example.net/elements/card.html" }
  },
  "secret": true
}
```

- `frame.url` は、iframe の中のページの URL のうち、オリジンとパスだけです。`?` 以降と `#` 以降は書けません。
  決済の iframe などでは、読み込むたびに変わる値が `?` 以降に付くためです。パスがない場合も `/` を付けます。
- 実行では、最上位のページに直接埋め込まれた iframe のうち、中のページの URL のオリジンとパスが `frame.url` と
  一致するものの中で、要素を探して操作します。URL は Chrome の翻訳で変わりません。
- 一致する iframe がない場合は、提供元の更新で変わる文字を除いて比べます（#191）。決済サービスなどの iframe の
  ページの名前は、`elements-inner-card-d60a909b….html` のように、更新のたびに変わる文字（ハッシュ）を含むためです。
  パスを区切り（`/`、`-`、`_`、`.`）で分けた各部分のうち、16 進数の文字だけで 8 文字以上のものを除きます。
  `card` や `iban` のような語と、`v3` のような部分は除かないため、別の欄の iframe や別の版のページとは一致しません。
  この比べ方で見つけた場合は、実行履歴の「補足」に、記録時と実行時のページの名前を残します。
- 一致する iframe が表示されない場合は、要素と同じく待つ上限の時間まで待ち、見つからない iframe の URL を示して
  停止します。やり直しの対象です。
- 一致する iframe が 2 つ以上ある場合は、どれにも入力せずに停止します。入力値を意図しない欄に入力しないためです。
- `frame.url` のサイトは、フローの `origin` か `extraOrigins` にある必要があります。記録では、最上位のページと
  別のサイトの iframe の中で操作すると、そのサイトを `extraOrigins` に加えます。実行の前に、そのサイトの操作の許可も
  確かめます。手順の `origin` は、最上位のページのサイトです。
- 記録中に、許可のないサイトの、画面に見える iframe があると、サイドパネルの最上部に知らせを出します（#230）。
  知らせの［このサイトを許可して記録を続ける］で許可するまでは、その iframe の中の操作を記録しません。
  広告や計測のための見えない iframe（幅か高さが 30px 未満、非表示、画面の外）は知らせません。
- サイトごとの止める要素の指定は、最上位のページのサイトの指定と、iframe のサイトの指定の両方を使います。
- 次のものは扱いません。iframe の中の iframe（2 段以上の埋め込み）、一覧の行と「次へ」が iframe の中にある場合、
  iframe の中でのページの移動の記録、要素の選択モードで iframe の中の要素を選ぶこと、iframe の中のページの
  PDF の保存（`savePdf` は最上位のページを保存します）。
- iframe の中では、実行中・記録中の枠を表示しません。最上位のページの枠で示します。
