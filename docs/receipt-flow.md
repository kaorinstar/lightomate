# 領収書のフローの作り方

購入履歴から、指定した月の注文の領収書を 1 件ずつ開き、PDF として保存するフローの作り方です（#8）。
毎月初めに、前月分の領収書をまとめて保存する作業を、1 回の実行で終えられるようにします。

拡張機能に、特定のサイト向けのフローは含めていません。サイトごとに画面の作りが異なり、予告なく変わる
ためです。この手引きに従い、利用するサイトに合わせてフローを作ります。

## 使う前に確認すること

- **利用規約**：サイトによっては、利用規約でロボットなどの自動化ツールの使用を禁じています。ログインした
  状態の購入履歴を自動で操作することが、その禁止に当たる場合があります。フローを作る前に、利用するサイトの
  利用規約を確認してください。確認と判断は利用者が行います。手順の間隔を長くしても、規約で禁止されている
  操作が認められるわけではありません。
- **ログイン**：フローは、ログイン済みの Chrome の画面をそのまま使います。実行の前にログインしておきます。
  実行中にログインの画面が表示された場合は、一時停止します。ログインを済ませて［再開］を押すと続きから
  実行します。

## できあがりの形

完成したフローは、次の順に動きます。

1. 購入履歴の一覧を開く。
2. 一覧の注文の行を、上から 1 行ずつ処理する。最後の行まで処理したら「次へ」で次のページに進む。
3. 行の注文日が対象月より前の場合は、繰り返しを終える。一覧が新しい順に並んでいるため、それより後の行と
   ページには対象月の注文がないためです。
4. 行の注文日が対象月に含まれる場合だけ、次の 5〜7 を行う。
5. 注文日と注文番号を読み取る。
6. 領収書のリンクを押して、領収書の画面を開く。
7. 領収書の画面を PDF として保存する。保存した後は、自動で一覧の画面に戻る。

保存先は、Chrome のダウンロード先フォルダーの中の次の場所です。同じ月を 2 回実行しても、同じ領収書の
ファイルが 2 つにならないよう、同じ名前のファイルは上書きします。

```
<ダウンロード先>/Lightomate/領収書/<サイトのホスト名>/<対象月>/<注文日>_<注文番号>.pdf
```

例の JSON は [`docs/examples/receipt-flow.json`](examples/receipt-flow.json) にあります。架空のサイト
（`https://shop.example.com`）向けの例のため、そのままでは動きません。次の手順で、利用するサイトに合わせて
書き換えます。

## 記録から繰り返しを作る方法

1 件目の注文の操作を記録し、その範囲を各行で繰り返す手順に変えられます（#167）。JSON を書かずに、繰り返しの
部分を作れます。

1. 購入履歴の一覧を開き、サイドパネルの［記録開始］を押します。
2. 1 件目の注文で、領収書を開くまでの操作を行います（例：［領収書等］→［明細書］）。
3. サイドパネルの記録中の区画で［繰り返しにする］を押します。
4. 繰り返す手順に印を付けます。既定では、一覧の 1 件の中を操作した最初の手順から、最後の手順までに印が付いています。
   ページを開く手順（一覧のページを開いた手順）には、印を付けられません。
5. 「このページの一覧 10 件で…」の件数が、1 ページの注文の数と同じことを確かめ、［10 件で繰り返す］を押します。
6. ［記録停止］を押し、フローとして保存します。

「1 件の中」の印が付いた手順は、注文ごとにその 1 件の枠の中で要素を探します。「ページ全体」の印が付いた手順（行の外に開く
小さな枠の中の要素など）は、ページ全体から探します。

この方法で、各行で同じ操作を行う部分、次のページへの移動、対象月の条件を作れます。それぞれの作り方と注意点は
次のとおりです。PDF のリンクがない画面の保存は、保存した後に編集画面のブロックで加えます。

- **対象月の条件**（#183）：記録中に、1 件目の注文で注文日の文字を押しておきます。［繰り返しにする］の欄で、その手順の
  「この日付が対象の月の行だけ行う」に印を付けます。実行するときに入力する対象の月（既定は前月）の注文だけを処理します。
  年月のパラメータ（`month`、説明は「対象月」）をフローに加えます。
  「対象の月より古い行に達したら、残りの行とページを開かずに終える」は、既定で印が付いています。購入履歴のように
  新しい順に並んだ一覧で使います。並び順が新しい順でない一覧では、印を外します。
  印を出すのは、記録した文字が日付として読める手順だけです（docs/flow-format.md の「日付の読み取り方」）。
  注文日が表示されない行がある場合は、その行で停止します。
- **PDF の保存**：PDF のリンクがない画面は、繰り返しのブロックの中に［PDF を保存］のブロックを置きます。
- **次のページへの移動**（#182）：記録中に、1 件目の注文の操作を終えて一覧に戻った後、一覧の「次へ」を押しておきます。
  ［繰り返しにする］の欄で、その手順の「このクリックで次のページへ送る」に印を付け、［全ページで繰り返す］を押します。
  1 件目の操作の後から「次へ」までの手順（［戻る］など）と、「次へ」の直後のページの移動は、手順から除きます。
  除く手順には、欄の中で「→ ページ送りに置き換えるため、手順から除きます」と表示します。
  「次へ」が見つからないページを最後のページとし、最大 10 ページまで繰り返します。「次へ」は、ページ番号の数で位置が
  変わっても見つかる指定（例：`li.a-last > a`）で探します。そのような指定を作れない「次へ」には、印を出しません。
  その場合は、ブロックの一覧の「…の各行で繰り返し、次のページへ進む」を置いて行と次へのボタンを選び、変換した
  繰り返しの中のブロックを移します。
- **領収書のリンクがない注文**：キャンセル済みの注文などで［領収書等］がない行は、飛ばして次の注文へ進みます。
  飛ばした注文は、実行のカードと実行履歴に表示します（#174）。
- **PDF ファイルとして開く領収書**：記録中に領収書のリンクを押して PDF が開いた場合は、そのクリックが自動で
  「リンク先のファイルを保存」の手順に変わります（#172）。保存先は `Lightomate/<フロー名>/<実行の日時>` です。
- **明細書が複数ある注文**（#185）：「リンク先のファイルを保存」の手順は、押したリンクと同じ種類のリンク（リンク先の
  形が同じもの）をすべて保存します。「明細書／適格請求書 1」「明細書／適格請求書 2」がある注文では両方を保存し、
  2 件目の名前の末尾に `_2` を付けます。
- **ファイル名を注文日と注文番号にする**（#179）：記録中に、1 件目の注文で領収書のリンクを押す前に、注文日と注文番号の
  文字を押しておきます。［繰り返しにする］の欄で、その手順の「この文字をファイル名に使う」に印を付けます。ファイル名は
  印を付けた順に並び、`2026年9月11日_503-2426301-0153427.pdf` のようになります。「ファイル名の先頭にサイト名を入れる」に
  印を付けると、先頭に `www.amazon.co.jp_` が付きます。同じ名前のファイルは上書きするため、同じ月をもう一度実行しても
  増えません。同じ実行の中で同じ名前になった場合（注文日だけを使い、同じ日に複数の注文がある場合など）は、番号を付けて
  別名で保存します。Chrome の翻訳を有効にしていると、ファイル名も翻訳後の文字になります。

記録したときと実行するときで、Chrome の翻訳の有無が異なる場合、行の外の要素を表示の文字で探す手順は、要素が
見つからずに止まることがあります。記録と実行は、翻訳の設定を同じにして行います。

## 作り方

### 1. 購入履歴の一覧を開く操作を記録する

1. 利用するサイトにログインし、購入履歴の一覧を開きます。
2. サイドパネルの［記録開始］を押し、購入履歴の一覧をもう一度開きます（ブックマークやメニューから）。
3. ［記録停止］を押し、フローとして保存します。

記録したフローの最初の手順（`navigate`）が、購入履歴の一覧の URL になっていることを確かめます。

### 2. 画面の要素の指定を調べる

例の JSON で、次の要素の `selectors` を、利用するサイトの画面に合わせて書き換えます。`selectors` には、
CSS セレクター（画面の要素を指す書き方）を書きます。

| 場所 | 指す要素 | 例の値 |
|---|---|---|
| 注文の行（`forEach` の `items`） | 一覧の注文 1 件分を囲む要素。すべての注文に一致させます | `tr.order-row` |
| 次へ（`nextPage`） | 次のページへ進むボタンかリンク。押せる状態のものにだけ一致させます | `a.next:not(.disabled)` |
| 注文日（2 つの `condition` と 1 つ目の `extract`） | 行の中の、注文日の文字 | `.order-date` |
| 注文番号（2 つ目の `extract`） | 行の中の、注文番号の文字 | `.order-number` |
| 領収書（`click`） | 行の中の、領収書を開くリンク | `a.receipt` |

調べ方の一例です。Chrome の開発者向けの機能（デベロッパー ツール）を使います。

1. 購入履歴の一覧で、調べたい要素（注文日の文字など）を右クリックし、［検証］を選びます。
2. 画面の右か下に、ページの構造が表示されます。選んだ要素の行が色付きで表示されます。
3. その要素の `class` や `id` の値から、CSS セレクターを決めます（`class="order-date"` なら `.order-date`）。

注文日・注文番号・領収書の 3 つは、`"scope": "item"` のまま残します。処理中の行の中だけで要素を探すためです。

### 3. 例の JSON を当てはめる

1. フローの管理画面で、手順 1 で保存したフローを開きます。
2. ［JSON］のタブを開き、`steps` の 2 つ目以降に、例の JSON の `forEach` の手順を貼り付けます。
3. `params`（対象月の入力欄）と `interval`（手順の間隔）も、例の JSON から貼り付けます。
4. 手順 2 で調べた値で、`selectors` を書き換えます。
5. 領収書の画面の URL を、`"type": "navigate", "cause": "page"` の `url` に書きます。注文ごとに URL が
   変わる場合は、どれか 1 件の URL で構いません。この手順は、画面の移動が終わるのを待つためのもので、
   その URL を開くわけではないためです。
6. ［JSON を保存］を押します。形式に誤りがある場合は、編集欄の下に理由が表示されます。

### 4. 少ない件数で試す

最初は、注文が少ない月を対象月に選んで実行します。実行するとき、サイドパネルに対象月の入力欄が表示され、
既定では前月が入っています。

### 一覧が新しい順でない場合

例の JSON は、購入履歴が新しい順（注文日の新しいものが上）に並んでいることを前提にしています。古い順に並ぶ
サイトや、並び順が決まっていないサイトでは、`forEach` の最初の `if`（`"before"` と `{ "type": "break" }`
の手順）を削除します。削除しない場合、対象月の注文を処理しないまま終えることがあります。削除した場合は、
最後のページまで開くため、`maxPages` を一覧のページ数より大きくします。

## 確認すること

- 対象月の注文の領収書が、すべて PDF として保存されている。
- 保存した PDF で、背景の色や罫線、表の配置が画面と同じである。異なる場合は、`savePdf` に
  `"mode": "screen"` を加えて、画面の表示のまま保存します（`docs/flow-format.md` の「`savePdf`」）。
- 対象月以外の注文の領収書が保存されていない。
- 同じ月を 2 回実行しても、同じ領収書のファイルが 2 つにならない。

## 止まったときに確かめること

| 止まった理由 | 確かめること |
|---|---|
| 行が見つからない、または 0 件で終わる | 注文の行の `selectors` が、一覧のすべての注文に一致しているか |
| 行数が上限を超えている | `forEach` の `max`（例では 200）を、全ページの注文の合計より大きくする |
| ページ送りの上限に達した | 一覧が新しい順に並んでいるか、`"before"` の条件の `selectors` が注文日を指しているか。対象月より古い行で繰り返しを終えるため、通常は上限に達しません。古い行に達しない場合は、`maxPages`（例では 12）を、一覧のページ数より大きくする |
| 日付を読み取れない | 注文日の `selectors` が、日付の文字だけを含む要素を指しているか。「2026年8月3日」「2026/8/3」などの表記だけを読みます（`docs/flow-format.md` の「日付の読み取り方」） |
| 一覧のページへ戻った後に停止する | 一覧が、URL を開き直しても同じ内容で表示されるページか（`docs/flow-format.md` の「行の中でのページの移動」） |
| 領収書の PDF が Chrome の表示画面で開くだけで、保存されない | 領収書のリンクの `click` の手順に `"download": { "path": "…", "from": "link" }` を加えます。クリックせずにリンク先のファイルを保存します（`docs/flow-format.md` の「リンク先のファイルの保存」）。記録中に PDF が開いた場合は、自動でこの指定になります |
| 領収書が画面ではなく、PDF などのファイルとしてダウンロードされる | 画面を PDF にする `navigate` と `savePdf` の代わりに、領収書の `click` の手順に `"download": { "path": "Lightomate/領収書/{{site.host}}/{{month}}/{{orderDate}}_{{orderNumber}}", "onConflict": "overwrite" }` を加えます（`docs/flow-format.md` の「サイトが提供するファイルのダウンロード」） |
| 領収書が新しいタブで開く | 領収書の `click` の手順に `"newTab": true` を加え、`savePdf` の後に `{ "type": "closeTab" }` を加えます（`docs/flow-format.md` の「`closeTab`」） |

各項目の詳しい説明は、[`docs/flow-format.md`](flow-format.md) の `forEach`、条件、`extract`、`savePdf` の節にあります。
